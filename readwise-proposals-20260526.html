Proposal 1: PRATA Trust Fabric 修订

Life OS PRATA Multi-Agent 三存活模式
把 PRATA 修订为"单写入（single-writer）信任控制平面"，而非 agent mesh；Google Runtime 只负责并发执行，所有委托、提交、审计、回滚统一收口到 PRATA。

架构约束（不可妥协）

  • 只允许 3 种模式：Pipeline / Orchestration / Generator-Validator
  • 禁止 peer collaboration 作为生产主路径
  • 所有外部写操作单线程化：只由 Manager/Commit Agent 经 PRATA 执行
  • Sub-agent 只贡献 intelligence，不贡献 final decision

痛点

  • 原方案最大风险：把"分布式 runtime"误当"分布式决策"
  • 责任边界不清：谁有权写、谁能委托、谁对结果负责
  • 错误会级联放大：agent 互聊互改时 debug 成本指数上升
  • 缺少 clean-context 校验层
