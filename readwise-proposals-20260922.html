Proposal 1 / 1

Laya「小脑」计划——把 typed decision 下沉到本地 ✅🔬

信号源：@mizorewww 推文 · mizorewww/laya-mlx（⭐3,775）· HF 权重 · 亲测：安装 6.5s / 短决策 12-13ms / 峰值 943.6 MiB / 工单路由正确（billing p=0.89）

0 · 核心主张

Agent 系统中高频、固定标签的决策（eval 结果分流、judge 分诊、桌宠行为选择）应从云端生成式 LLM 下沉到本地 typed-decision 分类器，laya-mlx（~10ms / <1G 内存 / 零 token 生成 / 校准概率输出）承担第一级分诊，云端 LLM 只看低置信长尾。
两点保险：本主张不含「Laya 能做语义判断」（§7 专攻此点）；M1 基准为证伪而设计——两周内出数字，不达标即降级为观察项。这不是「小模型替代 LLM」，是给 Agent 装小脑：反射归本地，思考归云端。

1 · 锁定的痛点（只打两个）

痛点 A（主）：AI Coding Eval 的 judge 双重税

  • 一致性税：LLM judge 与人工一致性有限，低置信结果仍需人工复核；
  • 成本税：每个 case 都过一次 judge，费用随 case 数线性增长，复核再付一遍；
  • 锁定切面：eval 失败结果的落桶（build / logic / env / 数据问题 / 需人工，固定 5 标签）与 judge 分诊（哪些 case 值得动用昂贵 judge）。两者都是分类形状，恰是 Laya 的形状（quick start 即企业工单路由：billing 0.89 / technical 0.08 / sales 0.03）。

痛点 B（辅）：Micro-pet 缺一颗「条件反射」脑

  • 桌宠需要亚秒级、常驻后台、零云依赖的行为决策；本地 7B LLM 太重（数 G 内存、百 ms 至秒级），规则引擎太死；
  • laya-mlx：峰值 943.6 MiB、短决策 7-13ms、已有 60 dec/s 玩贪吃蛇实证，生态有 laya-mlx-swift 可原生嵌入 macOS 应用，正好是「小脑」规格。

范围外（明确不做）：不主张 Laya 直接判代码正确性；不做 fine-tuning（除非 M1 差一口气）；不做跨平台移植。

4 · ROI / 影响估算

  • 费用：若 judge 调用占 eval 管线云端开销大头，级联减半调用即同比例省减；单次分诊边际成本从 API 牌价降至电费约等于零。
  • 延迟：本地 ~10ms 对比云 API 往返数百 ms 至秒级，高频决策环可闭环（60 dec/s 已证）。
  • 隐私：分流类决策不出设备、代码不出本机——企业场景的直接合规卖点。
  • 资产复利：cascade 模式可平移至 Life OS 的 memory triage（登记为下一候选）；typed decision + 本地推理是 Agentic Engineering 基础设施级主题，早期动手即认知复利。

421M 分类上限双向编码器无推理链；中文/代码分布可能域外只做固定标签路由；golden set 先行；加测 322M 多语言版；必要时域内微调
MLX 平台锁定仅 Apple Silicon；「CoreML 降 64% 功耗」无独立信源同一权重存在跨平台实现可逃生；推理藏于 MCP 接口层（laya-mcp 已存在）；CoreML 数字当传闻处理
级联静默误判自动采纳错误标签会无声扩散只对高置信 auto-accept；5% 人工抽审 + 全量审计日志

6 · 立即行动（本周三件事）

  • 冻结 golden set（3h）：抽 200 条已有人工结论的历史 eval 案例，标注 5 分类标签，存入公开 repo。
  • 跑四方基准（4h）：uv 环境已就绪（安装实测 6.5s）；单脚本输出 laya×2 / 云 judge / 朴素基线四组一致性、延迟（512/2k/4k 三档）与 ECE。
  • 审 license + 长输入压测（2h）：确认上游权重与移植仓库的再分发条款；定标长输入延迟曲线。

7 · 诚实挑战（自己先拆台）

  1. 物种错位（核心疑点）：Laya 不是「更快的 LLM」，是另一个物种——双向编码器单次前向分类，没有思维链、没有组合推理。「比 JEV 快 50 倍」是拿分类器比托管 API，修辞大于信息。真正的问题：你要的决策是不是分类形状的？代码正确性判断很可能不是（需读语义）；若 M1 一致性 <75%，本 proposal 对 eval 的主张即死，只剩 triage 幸存。可证伪性是本计划的骨架：M1 就为让它早死或早活。
  2. 朴素基线威胁：落桶任务可能简单到 TF-IDF+LR 就能做。若 laya 无显著优势，护城河消失，仅剩「校准概率」一个差异点。故 M1 强制纳入朴素基线，防归因错误。
  3. 校准漂移：calibrated probabilities 在上游分布上做的；中文加代码混合域上 confidence 可能系统性偏乐观，级联阈值随之失真。必须先画域内 reliability diagram 再定阈值。
  4. 延迟的条件性：13ms 是短决策；贪吃蛇 60 dec/s 是极短输入。真实 eval 输入常达数千 token，注意力开销随之放大，该曲线未测——立即行动第 3 件事就是补这个洞。
  5. 新鲜度与机会成本：repo 数天历史、单人维护、本周热点；真正的资产是「typed decision 下沉本地」的架构模式与自建 golden set，不是这个 repo。且每周 4-6h 是从 Life OS / K12 挤出来的，M1 两周内不出数字即止损。
