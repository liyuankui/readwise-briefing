P1 · L2 NL 断言层引入 Jev 类专用决策模型

判定与证据分离

信号：Using TypeSafe's Jev for Evals（✅ 全文亲测）· 连接：昨日 NL 断言层 PoC
Jev 以 $160/百万答案承担 L2 全量判定，生成模型只对被路由的少数样本补证据，使 NL 断言从「小样本试探」升级为全量、可复跑、可显著的日常评测设施。

🧱 映射设计

Jev 问题schema 字段示例
Noulverdict（pass 概率）+ confidence「diff 是否消除该缺陷？」
Choicefailure_mode 枚举wrong_api / hallucination / incomplete / style
Score（≤10）severity 1-5失败影响分级

一次请求并行问 verdict/needs_review/failure_mode/severity，延迟几乎不增。局限对策：无理由输出→仅低置信/fail/分歧样本交廉价生成模型补证据供 L3 抽审；context rot→按断言裁剪缓存回放（32k 保守上限）；不能弃答→低置信=软弃权路由 L3。

Judge$/百万单轮月（日跑×双判）
Jev160$1.44~$86

较 frontier 月省 99.5%；同等预算样本 ×10，直接解「无显著差异」。成功标准：金标一致率 ≥85%、双判分歧 ≤10%、≥1 组 model×harness 差异 p<0.05、单轮 ≤$5/30min。里程碑：M1 rubric 原子化冒烟（1d）→ M2 旧基线双判 go/no-go（2-3d）→ M3 全量重跑+显著性（1w）→ M4 证据补全管道（2-3d）。

🔴 诚实挑战

  1. 91.5% 是第三方通用 rubric 成绩，code 域可能更低；M2 实测 <80% 即退化为初筛——M2 就是证伪点。
  2. DeepSeek V4.1 Flash 一致率 93.5% 反超且自带理由——「专用决策模型」的溢价应以 M2 数据裁决而非叙事。
  3. 若 57-59% 根因在 judge 之外（任务漂移/金标噪声），换 Jev 无解，先做误差归因。

P2 · 谄媚防护层

无新证据，不改立场

信号：Why LLMs Agree With You（✅）· 连接：judge 设计 + 昨日入库的 GOAL_RESTATE/DEEP_QUESTION
谄媚是系统性偏差非偶发 bug：RLHF 把准确/礼貌/讨喜压成单一偏好，「同意用户」成好评捷径。应用层三落点防护：评测 judge、既有 prompt 探针化、日常协作系统指令。

🧱 三落点设计

  • judge 谄媚免疫：盲评组装时剥离模型名/作者/金标倾向三类泄漏源；配对提示（中立版 vs 带倾向版）入 pipeline，偏移超阈值告警
  • GOAL_RESTATE v2：复述只许中立转写字面目标+显式假设，禁猜「您真正想要」；本人修正后 AI 接受须指明「哪条新证据推翻原判断」，无据须先反驳一次——升级为同步测量「无据改口率」
  • 三条系统指令：偏好可从、断言认证据（改口必须引新证据）；先答后知（先独立评估再接收用户倾向）；独立校验（数字/日期/接口行为禁凭记忆断言）

成功标准：配对偏移降至基线 50% 以下且有效纠正接受率不降（防走反向极端成固执）；连续 4 次周五回顾无据改口 0 次。投入 <5 人日，judge 可信度是全部评测结论的乘数。

⚡ 本周三件事

  1. 扫 judge prompt 与上下文组装代码，列泄漏源清单
  2. 写 10 组配对提示，跑偏移基线
  3. GOAL_RESTATE v2 上线，本周五回顾实测

🔴 诚实挑战

  1. 循环性：用 AI 检测 AI 谄媚，检测工具自身可能迎合预期——需独立会话交叉复核，无法根除。
  2. 天花板：系统指令改不了模型内部偏好，此层是护栏非地基；换裸 prompt 入口防护即失效。
  3. 样本量：每周一次回顾，4 次测「零改口」统计力近乎为零——只配当烟感器，不配当证明。

P3 · 无人值守任务验收框架（Trust & Eval 第一块砖）

先筑信任，再扩自治

信号：Claude Code on Autopilot（✅ 付费墙前内容）· 连接：Life OS / 已有 cron 简报管道
瓶颈不在调度（cron 已稳），在信任验收。先以「validation harness + 可读报告」做成平台无关资产，再按任务特性选云地——断言即 Eval，报告即 Trust 之证。

🧱 迁移决策与首个 Proactive Agent

任务决策理由
Readwise 简报（现有 cron）不迁，加 harness已全闭环，上云仅换运行时
事件触发类（Git watcher 等）上云试点本地无事件触发，合盖可跑
inbox 清理 Agent首个新增唯一每日必触手动动作：IRA 分类→归档→双向链接→一行报告

关键认知：Routines/Cowork 底层同为 headless 冷启动，迁云不解决上下文保持。harness 断言示例：发布页含今日日期、journal 落盘、最新 commit；报告格式「正常一行 Clean，异常才展开」（防报告反噬成注意力税）。里程碑：M1 存量例行配断言（W1）→ M2 guardrails（专用 deploy key 只写发布仓、hooks 白名单、失败必达）（W2-3）→ M3 inbox Agent 上线（W4）→ M4 一任务上云双跑（W6）。

成功标准（30 天）：断言覆盖率 100%、静默失败 0、失败→通知 ≤5 分钟、新 Agent 周省 ≥30 分钟。

🔴 诚实挑战

  1. 「最高频手动动作」是推断非测量——先记录一周实际频次，再定首个 Agent。
  2. 信号单一且有付费墙：Cowork 合盖运行的真实可靠性/成本/数据边界未经独立验证。
  3. 报告反噬：若报告需人日读，自治反成注意力税——严守心跳格式。

P4 · 能力资产化：练级场产物即能力证明

把反驳日志/case bank 升级为可署名展示的能力资产

信号：DeepSeek 跨界招聘（⚠️ JD 未核验）· 教学≠解题 · cses.fi/book.html（✅）
头部 AI 雇主开始为竞赛/开源/深耕定价——不新增训练项目，把练级场日常产物（反驳日志/case bank/轮值记录）规格化为「能力护照」，并以「教 AI 审查」为讲师团 L4 顶点课：教是最深的学。

🧱 设计要点

  • case 五字段：场景 / AI 原输出 / 误因 / 反驳依据 / 复盘（+脱敏规范）
  • 讲课资格 = case 质量，非资历——「教」须分层，1v1 带教亦算教，防造新壁垒
  • CPH/CSES 定位：在职工程师仅 L1 自选热身（刷题是被替代的旧证明）；应届/转岗可作 L0→L1 桥接

成功标准：≥20 条双评审 case、反驳成立率 ≥80%、case 复用率 ≥30%、≥1 门 L4 课由非资深主讲、季度关键人零流失。成本：每人每月 ≤2h 规格化+脱敏。

🔴 诚实挑战

  1. 定价权质疑（最重）：现行晋升看业务影响与 scope，若晋升委员会不为「反驳 AI」定价，资产化近心理安慰——靠 M5 季度数据裁决，无定价权即收缩为学习工具。
  2. 信号过拟合：招聘推文未核验，「不设专业限制」或仅限少数跨界岗。

🧱 五原则 × 场景

#原文观点Kyle 场景·动作边界
