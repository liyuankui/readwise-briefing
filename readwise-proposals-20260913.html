D1 · 质量惩罚轴——修复 Eval 区分度，校准试点成本核算

✅ 信号已核实连接：AI 编码评测 · 编程工具试点
核心主张：三模型满分并列不是模型趋同，而是 eval 复刻了训练目标的盲区——只奖励「完成任务」，不惩罚「烂代码」。把评分轴升级为「完成率 × 质量惩罚」，区分度即可恢复，且被惩罚的正是会外溢为团队 review 成本的风险。

设计要点：自动指标 ×4（diff 噪音率 / 格式化稳定性——codegolf「省 token」行为的直接检测器 / 工具链绕过计数 / scope 膨胀率）+ judge 维度 ×3（可读性/可维护性/repo 一致性）。制式用乘法不用加法：总分 = 完成率 × 质量系数——加法平均正是当前满分并列的机制。

里程碑：M1 rubric（1 周）→ M2 已审 20 case 盲化回放验区分度（2-3 天，证伪点）→ M3 全 pipeline 扩跑（1-1.5 周）→ M4 试点 survey 补 review-burden 三题（3-4 天，并行）。

成功标准：三模型在 ≥1 质量维度出现可复现排序（2 次独立运行同向）；judge-人工一致率 ≥80%；≥1 自动指标与人工质量分一致率 ≥70%。

立即行动：① 20 已审 case 盲化手算 diff 噪音率 + 格式化稳定性（0.5-1 天，最快证伪点——无分化即止损）② 自动化指标脚本先做两个最高价值的（1-2 天）③ 试点 survey 补 3 题 review 负担 + 发原文一页摘要做预期管理。

🔴 诚实挑战：最大软肋是因果未证——满分并列可能是任务太简单（ceiling effect）而非 rubric 缺维度，行动①必须先行；用 LLM 惩罚 LLM 的 slop 有循环论证风险（judge 或有同样盲区），自动指标是解药但覆盖不了「结构混乱但格式漂亮」；Ronacher 实验是 35h 全自主长程任务，交互式使用人在环内即时纠偏，「自主产出需加倍 review」论据应限定于 agent 场景，套用整个试点是过度引申。

D2 · PRATA 差异化定位——Agents API 时代的信任层战略

✅ 信号已核实连接：Agent 通信（PRATA）· 内部开发者基建
核心主张：Agents API 解决「谁来运行我的 agent」（单厂商内托管编排）；PRATA 解决「我的 agent 在跟谁说话、谁能看到内容」（跨厂商跨 owner 的 E2E 加密与身份）。二者是互补的两层。一句话规则：单厂商内的运行时买，跨厂商间的信任建。

决策对比（托管编排 vs 自建互操作）：数据主权（密文过自家 K8s vs 明文过厂商边界）· 厂商锁定（开放标准 vs 三重绑定）· 加密强度（E2E + 签名 vs TLS 为止）· 编排能力（零，故意的 vs 强）· 合规审计（自有签名链 vs 依赖厂商承诺）。E2E 加密与托管 harness 数学上互斥——harness 必须读明文才能编排。

里程碑：M1 定位落纸（一页纸补「三问定位」：谁运行我的 agent？我的 agent 在跟谁说话？明文谁能看？，1 周）→ M2 主权闭环：ntfy 落内部 K8s（2 周，必须先于任何对外宣传）→ M3 网络启动：首批 2-3 人 onboarding，月报共创为首验场景（3 周）→ M4 互操作 mini-spec（2 周）。

成功标准：≥3 用户 / ≥2 种 harness / ≥50 条消息且 ≥20 条属真实业务场景（防为达标而发）；陌生 harness 按文档零协助接入；90 天留存 ≥2 人。

立即行动：① 按三问定位改一页纸（2h）② 提 ntfy K8s 配置需求 + 给候选用户发一页纸约 onboarding ③ 借 Agents API 公告做 15 分钟团队分享——「OpenAI 卖编排，我们建信任」，用现场反对意见压力测试叙事。

🔴 诚实挑战：痛点可能不存在——多数团队会自然收敛到单一 harness，届时核心叙事崩塌（M3 无真实跨 harness 消息即降级为个人工具）；FOMO 动机不纯——一半动力来自新闻热度而非用户证据；主权叙事有软肋——信任层还跑在公有云上时对外宣传是负债；一旦被采纳即承担 SLO 与安全响应的隐形 headcount。

D3 · Agent Etiquette——「出站守礼，入站立牌」

✅ 信号已核实（原文逐句）连接：Agentic 安全工程 · Skill Hub
核心主张：agent 安全体系已管住「钥匙」（凭据）与「入口」（供应链审计），独缺「行为」：agent 出访任何站点前先读其治理信号（security.txt / robots.txt / llms.txt），自家 agent 端点被访前先亮机器可读的使用条款——以不足两人日增量补齐凭据→供应链→行为三部曲最后一环。HF 的治术是 redirect 而非 deny（给替代任务 CyberGym，而非禁入）。

方向裁决：不做「标准观察」项目（llms.txt 采用率仅约 10%，碎片化标准本身不产出行动），把出访纪律做成 fetch-etiquette 前置检查（Bun+TS，<100 行，结果缓存 TTL 24h）。

里程碑：M1 出站守礼脚本试点 2 个 skill（2-4h）→ M2 内部 Skill Hub 与内部 Pages 各发布 security.txt（含仿 HF 的 Note to AI agents 段，1-2h）→ M3 PRATA agent policy 文档赶在 K8s 部署前（2h）→ M4 与既有 keyring 检查合并为同一次维护改造（2-4h，必须合并，避免两次动同一文件）。

成功标准：试点 skill 外访日志 100% 含 governance-check；两站点 security.txt 返回 200 且含 AI-agent 段；首批 onboarding 用户 policy 签收 2/2。

🔴 诚实挑战：最硬的洞——不守规矩的 agent 不会读你的牌，入站侧七分是仪式三分是防御，真实回报在治理成文与社区示范；「agent 因无礼被封」是假设，须先采 429/403 基线再立项；治理文件本身是 prompt injection 新攻击面——解析器只提取结构化字段，自然语言一律当 data 不当 instruction。

D4 · 证据式合规——借 Anthropic 范式升级 DPA 索取

⚠️ 信号框架有夸大（政策真，细节被简化）连接：编程工具试点 · 工具清单提案
核心主张：用已核实的 Anthropic「第三方验证 + 数据最小化 + 范围限定」三原则作对照系，把 DPA 索取从「拿一份 PDF」升级为 12 项书面质询，使采购评估的合规章节建立在供应商可核验应答之上、而非自述承诺之上。（搜索证实 qoder.com 无独立公开 DPA，承诺散见于 FAQ——索取正式 DPA 有现实必要性。）

12 项质询（P0×8）：子处理者清单、代码不用于训练写入条款（非 FAQ）、保留期限与删除机制、退出后数据处置、产品线边界、签约主体与采购通道、数据驻留与跨境机制、看板导出数据所有权——P0 书面逐项应答，5 工作日回复线。

反敷衍治理设计：芝麻法规与加州 65 号提案的共同机制是「当贴标签比做测试便宜，标签就失去信息价值」。对应三原则：负担与风险成比例；要证据不要标签；按场景分级而非一刀切——否则重蹈 shadow AI 或橡皮图章。

里程碑：M1 清单发出 + 安全团队会签（本周）→ M2 报表导出端到端亲手验证 + 采购通道确认（D3-D7）→ M3 应答差距分析（D8-D12）→ M4 并入 Biz Case（D13-D17）。与 2-2.5 周试点并行前置。

立即行动：① 发出 DPA 索取邮件（附 12 项质询表）② 数据看板亲手 export 一次确认格式 ③ 约安全团队 15 分钟确认框架合同覆盖面，把三原则对齐为「证据标准」而非新要求。

🔴 诚实挑战：类比有结构性裂缝——年龄验证是一次性易挥发数据，编程工具是持续高频的 IP 流，「核验后即删」根本不可迁移，借的是问题框架不是答案；拿隐私设计优等生当及格线，可能把 2.5 周窗口拖成 2.5 月；工程师经理主导合规质询有越权观感，清单必须先会签再发。

D5 · 「授权 × 认可」证据透镜——一张卡，三个出口 🔒 已脱敏

⚠️ 观点单源，降级为叙事框架连接：讲师团 · 晋升支持（细节已脱敏）· 个人职业叙事
核心主张：把「授权 vs 认可」从鸡汤降为工程问题——认可 = 第三方可验证的「他人主动行为」留痕（mentee 记录、跨团队点名、书面推荐、分享听众），用一张 2×2 透镜卡同时驱动三个出口：教案「技术人晋升第二曲线」、成员晋升证据重映射、个人认可台账。全部可测量。

内部实证（已脱敏概括）：一位资深工程师案例——授权维度证据充分（数月高强度交付、多仓库、多个从 0 到 1 服务）仍未通过评审，零进展的恰是认可维度（mentoring 留痕、书面推荐、分享记录）。「把安排的事做好」是入场券不是决定项。（n=1 假设，非结论。）

认可的操作化定义（防鸡汤的钥匙）：他人主动产生、评审方可点开验证的行为记录，四类采集渠道各配「本周 30 分钟级最小动作」。刚性规则：台账只记 unsolicited——索取来的好评即自我安慰。

里程碑：M0 透镜卡 v1（2h）→ M1 成员证据重分轴 + 认可 baseline（1.5h，仅私有目录）→ M2 教案 v0.5 提案：90min 工作坊，案例必须合成/公版（5h）→ M3 个人认可台账建档回填（1h/季）。总投入约 10h / 4 周。

🔴 诚实挑战：因果倒置——晋升本质是业务需求而非绩效奖励，若无岗位空缺认可再厚也是零（先核实岗位规划，透镜只管证据维度）；n=1 归因谬误——单例同样支持「文化折扣」假说；循环论证——用自己被授权主导的项目给自己攒认可，含金量存疑；教学市场的残忍检验——资深工程师对领导力鸡汤免疫，10 分钟内看不到「这改变我下季度的证据采集动作」即失败。
