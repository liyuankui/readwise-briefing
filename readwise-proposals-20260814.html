Proposal 2 · 信号：AI 淘汰软件工程中产 · ⚠️ 观点（单源，需交叉验证）

以"决策力"重构 Engineering Baseline

"AI 让代码变便宜、决策变昂贵——把决策力立为 Baseline 核心指标，价值从'写代码'迁移到'做对决策'。策略鲁棒：投资决策力多未来皆赢。"

🔒 锁定痛点（信号已在团队三处显形）

AI 缺质量门AI 生成代码架构/安全/领域正确性风险，出货快于人工拦截——只审查 diff，不审查决策
中能力低方法论Survey："高意愿·中能力·低方法论"，会干活缺系统判断框架
晋升 case 缺失做了大量工作却讲不出"哪些决策 mattered"——决策未被当作可晋升产出

三痛同根：判断力既不训练、也不度量、更不可见。

🗺️ 里程碑（聚焦判断力训练，非工具教学）

  1. M1 决策日志（ADR-lite）：每人每周 ≥1 条（背景/选项/取舍/否决项）
  2. M2 Code Review = 决策审查：AI-PR 附"为何选此/弃何/风险"，reviewer 评决策非 diff
  3. M3 Incident RCA = 判断健身房：多假设排序 + 证伪 + 系统修复 vs 症状修复
  4. M4 架构决策红蓝对抗（一人 defend，一人 attack）——亦是信任/脆弱共建
  5. M5 决策质量度量 + 晋升转化

✅ 成功标准

  • AI-PR review 决策命中率 ≥90%（盲评 10 PR/sprint）
  • RCA 质量评分 ≥3.5/4；系统性修复占比 ≥60%
  • 具备"决策档案"（≥5 ADR-lite）的工程师数：0 → 4（年底）

💰 ROI（向 Kirill/William）

叙事钩子："代码生产 AI 会接管，决策质量才是护城河——这是我对'AI 时代研发团队为何更值钱'的回答，附证据。" 三条硬 ROI：①事故成本规避（复发率↓）②AI 缺陷拦截价值 ③晋升转化 = 留任 + 能力。

⚠️ 诚实挑战

最尖锐：IKEA 的现实约束。IKEA 非硅谷初创，晋升标准可能根本不奖励"判断力"（按 tenure/能见度/政治）。前置动作：先用决策语言与 Kirill 对齐实际晋升标准，确认能兑换晋升再全面推开。另：晋升 case 缺失的真因可能是项目组合低能见度而非"决策不可见"——若工程师只是 ticket-taker，真约束是 scope，决策训练是其后话。

Proposal 3 · 信号：Tailscale 16年 SQLite WAL bug · ✅ Verified（743pts）

🔒 锁定痛点（已核实，出自自有事故档案）

PRATA 定位：用 SQLite 但不承担同类风险（单进程 Bun CLI、低频写）。真风险是平凡的——~/.prata/ 无备份、daemon 断连恢复。审计应落在此处，而非追猎珍稀 race condition。

  3. M3（1-2月）正面证明机制：POS 链路 Top 3 复发模式各加"未打补丁红、打补丁绿"的测试入 CI
  4. M4（2-3月）纳入 Engineering Baseline

✅ 成功标准

  • 重复故障率（已"修复"根因的同类复发）：<10%
  • 正面证明覆盖率（P0/P1 修复附能复现原故障的测试）：~0% → ≥70%
  • RCA 根因达成率（deterministic repro）：P0/P1 ≥80%

Proposal 4 · 信号：压缩即预测 · ✅ 经典定理（Shannon 1948）· ⚠️ 发现 cs336 repo 缺失！

压缩即预测 → CS336 五作业统一叙事锚点

"训练 LLM ⇔ 训练压缩器：cross-entropy loss = 每 token 平均编码 bits，降 loss = 压得更紧。一枚硬币串起五作业的'为什么'。"
🚨 先说真相（R·验证，不假设）

CS336 代码仓库在本机不存在（code.repo symlink 断裂，指向 kylli1 而当前用户是 kyle）。与 active.md 的 A1 🔄 标记矛盾。A2 截止是后天（8/16 周日）。压缩即预测加速不了"代码还没落地"这件事——理论预算 ≤3h，绝不挤占 A2 紧迫的动手时间。

🗺️ 里程碑（绑定 A2→A4）

M1·A2 讲清 attention（8/16）attention O(n²)=长程依赖信息量二次增长；FlashAttn 是 IO 层压缩非信息层压缩——划清边界。30min
M2·A1 补 cross-entropy5 步推导"loss<4.0 ≈ 每 token 5.77 bits"（bits = loss/ln2）。30min
M3·A3 scaling laws（8/30）Chinchilla = 参数容量须匹配数据信息量。1h
M4·A4 数据清洗（9/20）去重/质量过滤 = 降冗余、提信噪比。45min

🪙 10 分钟讲解框架（博客/团队分享可用）

  1. 钩子：DeepMind 用 Chinchilla 把 70B 压缩成更小文件——训练和压缩是同一件事
  2. Shannon：编码符号 x 的最优 bits = -log₂ p(x)
  3. 算术编码桥：序列最优编码 = -Σ log₂ P(xᵢ|前文)；会算条件概率 = 会压缩
  4. LLM 登场：LLM 就是 P(xᵢ|前文) 计算器；min cross-entropy = min 平均码长
  5. 落地：loss=4.0 ≈ 5.77 bits/token；scaling law=容量匹配信息量；去重=去冗余

Proposal 5 · 信号：Grok 4.6 长程 Agent · ⚠️ 推文（框架成立，分数不可验）

Long-Horizon Agent × Life OS：durable execution 脊（F22）

"长程能力改变的不是模型，是执行基底——Proactive Agent 须升级为'有状态·可检查点续跑·目标可对齐·预算可治理'的 durable execution 脊。脊先于马：脊是模型无关的，自主度是脊上一个旋钮。"

🔒 锁定痛点（跨 24h 会死在哪）

状态蒸发session 死/超 context → 全丢；run-agent.sh 一次性进程，无 resume
目标漂移跑 N 步后偏离原意图；agent 自述不可信
误差级联早错晚爆，无早门拦截
成本失控预算按 per-run 设，非 per-goal

根因唯一：无 durable execution 层。电路类比：现 Life OS 是组合逻辑（输入→输出一次性）；长程需时序逻辑——带状态寄存器（checkpoint）与反馈回路（eval gate）。

🗺️ 里程碑（长程任务脊 = SPEC F22，为 F12 前置）

  1. M1（1周）目标契约 + 检查点 schema：GOAL_CONTRACT.md（不可变：intent/success-rubric/budget-cap/forbidden）
  2. M2（1.5周）检查点运行时 + 续跑：run-longhorizon.sh emit checkpoint @ 各 phase + --resume
  3. M3（1.5周）漂移哨兵 + 无状态 eval 子 agent 评估门：每 checkpoint 重导目标 vs 契约
  4. M4（1周）预算治理 + Pilot @ 自主度 0（每门人批）

🧩 落地样板：首个自主 PR 的脊分解（自主度 0）

C0 Decompose → C1 Explore → C2 Implement → C3 Test → C4 Self-review → C5 PR，每门 = checkpoint 序列化 + 子 agent eval + 预算核 + 可续跑。自主度是旋钮：eval 证明某门可靠 → 自动放行。模型弱则人在环多，模型强则旋钮上调——脊不动。

✅ 成功标准

  • 24h 自主完成率：0% → ≥30%（诚实：2026 前沿仍难）
  • 漂移捕获率 >80%；续跑成功率 ≥95%；预算吻合度 >85%
  • Kyle 介入比：100%（单步全盯）→ 单任务 ≤2 次审批

⚡ 立即行动（本周）

  1. 写 Goal Contract schema（2h），拿 wiki-lint 一个修复任务当样本
  2. checkpoint 序列化器原型（4h），扩 run-agent.sh 在 3 点 emit + --resume
  3. 骨架试跑（半天）：拿已能做的短任务手工走 3 门脊，感受接缝 → lessons-learned
⚠️ 诚实挑战

长程 agent 在 2026 远未成熟，现在投入是否过早？此问误框了赌注——脊（checkpoint/契约/漂移哨兵/预算治理）是模型无关且架构必需：①F12 Intent-to-Delivery 已在 SPEC，无脊则坍缩为"意图→单发→祈祷"；②脊建在自主度 0（每门人批），今天就是结构化人辅工作流；③eval 门正是判断模型何时就绪的尺。真正该标的风险不是模型不够强，而是在无清晰首任务前过度投资通用层——骨架先行用在自身。
