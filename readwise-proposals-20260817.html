P1 · Life OS / OpenMAIC本地推理浪潮 ×6 合成

M4 Pro 24GB 本地优先 Agent 栈：分阶段落地路径

核心主张：用 4-bit 30B agent 模型（Muse Glimmer）作大脑、microVM（Docker Sandboxes + 自建 egress 白名单）作隔离墙，在 24GB MacBook 上跑通本地最小闭环；云端 API 降为复杂任务加速器，而非默认路径。
🎯 锁定痛点

Software Factory 现缺口：有 agent 无大脑（无本地推理档位），有大脑无墙（无隔离不敢开全自动）。24GB 现实边界：

边界事实
可行4-bit 30B（权重 <20GB）、纯文本模式（h3.c 路线佐证）、单并发
不可行8-bit 30B（权重即超限）、1M 全量 KV、稳定 10 并发 200+ tok/s（服务器级数字）、完整多模态
🚩 里程碑（选档→隔离墙→闭环）
阶段内容估算
M1 选档Glimmer 4-bit：MLX vs llama.cpp，实测 tok/s、内存余量、tool-calling，附云端同任务对照周末 ×1
M2 隔离墙Docker Sandboxes（Hypervisor.framework）+ egress 白名单1-2 周
M3 闭环墙内 YOLO 全自动完成 3 个真实小任务，Eval 判分2 周
M4 路由本地/云端双档路由，接 OpenMAIC 离线教室2 周

约 6 周，每周 10 小时业余节奏。

📏 成功标准
  • 4-bit Glimmer 生成 ≥15 tok/s、32k 上下文不 OOM（亲手实测，不引 benchmark）
  • 墙内 agent 外发非白名单流量被拦截（渗透自测）
  • 3 任务全自动完成且 Eval 通过
  • OpenMAIC 离线演示一次成功，零 token 费
💰 ROI

本地推理边际成本归零、隐私不出机；h3.c 与 Glimmer 部署即 CS336 A2 Systems 活体锚点；为团队沉淀一条可复制的本地 agent 安全路径。

egress 缺口：Sandbox 不挡外发（有 5.1GB 上传案例）白名单列入 M2 验收项
SGLang spec-decode 空输出（issue #20550）；MTP 提速依赖硬件默认关 MTP，实测后开
KV 膨胀挤压系统内存上下文限 32k，超限走云端

  2. 装 Docker Sandboxes，复现 egress 缺口并堵上（curl 外发测试）
  3. Needle 2（14MB）入 OpenMAIC 做边缘档 spike，半小时见分晓
🔥 诚实挑战

本地 30B vs 云端：76% 为官方口径，与云端旗舰的真实差距本机未测，M1 须补同任务对照；本地赢在零费、隐私、离线，非智力。若任务以复杂重构为主，本方案应缩窄为「隐私/离线档」，勿称替代。

24GB 是否伪约束：半真半假。真：8-bit、多并发、全量 KV 确不可行。假：若只做 orchestrator，14B 已够，「必须 30B」部分是营销叙事（见 08-17 推文）。该问任务分布，非显存数字。

最大隐藏风险：M3 若靠人工补 Eval，「自主」名存实亡——Eval 先行，agent 后跑。

P3 · 组织级效率目标 / AI Coding Eval观测验证主题 ×4 合成

AI 使用效能三层闭环：观测 × 对抗验证 × 收益追踪

核心主张：以「本地观测（谁在用、用得好不好）× 对抗验证（产出是否可信）× 收益追踪（省的时间去哪了）」构成数据底座，让组织级效率目标从叙事变为月度可查的仪表盘。
🎯 锁定痛点
痛点现状
收益追踪无数据不知谁在用 AI、用得好坏，效率收益无法汇报
Judge 无区分度内部代码库 eval 评分挤在 57–59%，选型排不出序
时间去向不明节省潜力已验证，再分配无追踪，收益不可转化

信号合成：AgentsView（4.9k stars，亲测 3.5 秒同步 191 会话，按日 GRADE+OUTCOME）补观测；Claude Code 负责人证言——LLM bug 已迁移至系统设计与跨文件上下文，对抗性 review 是对策，与内部 eval 最难 case 吻合——补验证方法；auto-mode 分类器拦 89% 危险命令 vs 人工 13.6%，但独立压测约 17% 漏报——机器闸须配人审；「不验证就转发 = 零价值」贯穿始终。四条拼成闭环，缺一不成。

🔥 诚实挑战

个人工具撑不起组织级叙事——对。AgentsView 只证「可测量」，不证「可规模化」；其价值是以最低成本把假设变数据，去换 Owner 与预算。连 M0–M1 数据都拿不出，买平台也是盲飞。

观测与监视一线之隔。GRADE 一旦挂绩效，数据即失真：人会优化指标而非工作。唯一防线是制度先行——聚合、自愿、不考核，违者数据作废。

「时间去哪了」可能测不准。工具测得了用量与质量，测不了时间再分配。若 M3 后无解，诚实结论是只报「采纳 × 质量」，时间转化另立研究。

🔥 诚实挑战

矩阵做完就过时？会。故交付物是刷新流程而非快照：价格列强制日期戳，每月 30 分钟例行刷新；决策依据是价格比区间（本周证据：4.8×~9.9× 量级差）而非精确单价——量级差远比单价稳定。若比价收敛至 <2×，矩阵自动降级为低优先级维护。

中英文代码库差异被忽略？真实盲区：主流 benchmark 偏英文，我们的代码库中文注释与业务术语占比高。缓解：eval 集强制 ≥30% 中文注释 case；若差异显著，矩阵升级第四维「语言适配度」。

eval 区分度不足：可执行 case 全满分可能只是 case 太简单，需加难度分层，否则「真实场景评测」一维名存实亡。
