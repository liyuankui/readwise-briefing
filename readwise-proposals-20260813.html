① Needle 2 接入 — SLM Agent Pareto 下界与置信门控边缘路由

核心主张：45M/14MB 模型不是又一个 benchmark 候选，而是 Kyle GAIA 的 Pareto 极端下界 + 一个可验证假设：作为 confidence-gated 前置路由器，低置信时升级到 8B，能否砍掉 50% 云端 API 调用？同时为 K12 提供 28MB 级离线推理引擎。
代号 Needle-Kyle-GAIA · 连接 SLM Agent Benchmark / K12 · 验证 ✅+🔬 · 工时约 7-8 工作日

🎯 锁定痛点

P1 路由层无智能（Kyle GAIA 的 QuestionRouter 是 regex，general 类无脑 fallback 搜索）｜P2 Pareto 曲线缺 sub-100M 下界（"多小算太小"无答案）｜P3 8B 本身准确率已低（qwen3-8b 仅 20%）｜P4 K12 依赖云端无离线方案。

📅 里程碑

M1 · 2h基线复现：M4 Pro 验证 tok/s≥800、RAM≤35MB
M2 · 1dAdapter：7 路由 label 注册为 tools，输出 {label,confidence}
M3 · 2d路由对决：regex vs Needle vs Needle+置信升级(θ=0.7→8B)
M4 · 2dPareto 曲线：45M→230M→8B→30B→70B 五点
M5 · 周末K12 边缘原型：RPi5 离线 quiz 路由 demo
M6 · 1d发布 GitHub Pages：数据+图表+复现脚本

📊 成功标准（可测量）

M4 Pro decode ≥800 tok/s ｜ RAM ≤35MB ｜ API 调用节省率 ≥30% ｜ Pareto 数据点 ≥5 ｜ RPi5 端到端延迟 <100ms。

💰 ROI

研究独创（首个公开 sub-100M agent router + 置信门控级联实验）｜补全 thesis 极端端证据｜K12 离线隐私零暴露｜HN/r/LocalLLaMA 话题性。

② h3.c 学习提案 — 用 antirez 33B 推理引擎，把"从零构建"拧到工业级

核心主张：花两周通读 h3.c（antirez 仅凭 C+Metal+FFmpeg 三依赖跑通 33B 多模态），亲证 "Python/PyTorch 运行时不是本地推理的必要条件"，为 CS336 补工业级推理引擎下半程，为 opencode-proposal 提供"本地依赖下限在哪"的硬数据点。
连接 CS336 / opencode-proposal / Rust · 验证 ✅+🔬 · 工时约 22h / 4 周 · ⚠️ 24GB 跑不了满血（H3 需 ~40GB）

🎯 锁定痛点

A. CS336 A1 止步 toy model forward pass，推理侧是黑盒（说不清 KV cache 布局/Metal dispatch）｜B. opencode-proposal 缺"本地推理能多轻"硬证据（现有路径全带 Python 依赖债）｜C. Rust 学习缺"系统级语言如何驾驭 GPU"活样本｜D. 24GB vs 40GB——但这恰好逼回"读引擎+文本路径"。

📅 里程碑（4 周 / 22h）

M1 · 3h工具链点亮：make test 退出码 0，记 M4 Pro 余量
M2 · 4h源码解剖图：文件树+prompt→MP4 数据流+Metal dispatch 点
M3 · 7h三子系统精读(KV cache/int8量化/SSD流式)+≤100行复现
M4 · 4h本地推理依赖债横评：h3.c vs llama.cpp vs MLX vs vLLM
M5 · 4h公开 writeup《一个零依赖推理引擎教给我们的事》

💰 ROI

⚡ 立即行动（本周）

③ TraceGuard — Reasoning Trace 侧信道防御与数据卫生

核心主张：既然同源弱模型能作解密预言机还原 API 返回的加密推理链，Agent 系统就必须把 reasoning trace 当 明文级敏感数据——trace 不可读 ≠ trace 不可解码，任何能观测响应者即能窃取沉淀在推理链中的私有上下文与凭据。
代号 TraceGuard · 连接 AI Security / credential-manager / PRATA · 论文 arXiv:2608.09867 ✅ · 工时约 6 人日 / 3 周

🎯 锁定痛点

P1 IP 经 trace 侧信道外泄（trace 是 prompt/代码/架构的蒸馏版，比最终回答更值钱）｜P2 凭据渗入 CoT（secret 被模型"推理过"残留于 trace，trace=第二秘密存储且无 TTL）｜P3 本地 trace 明文堆积（一次端点失陷即整库泄露）｜P4 多 Agent 放大面｜P5 代理/MCP/可观测工具记录响应即捕获可解码 trace。

📅 里程碑（3 周 / 6 人日）

M1 · 1d威胁建模+trace 流向审计：trace-flow 图+exposure register
M2 · 2dtraceguard sanitizer PoC：拦截响应→检测/分类/脱敏/标记
M3 · 1d凭据上下文隔离：tool-call 域内临时上下文，返回即脱敏
M4 · 1d本地持久化加固：store/journal/SQLite 内 trace 加密+TTL+purge
M5 · 1d自有 PoC 表征+公开 writeup（发方法不发 payload）

📊 成功标准

经 sanitizer 的 agent API 调用占比 100% ｜明文 trace 存量 0 条 ｜ secret 召回 ≥0.98 ｜ p95 延迟开销 <5% ｜脱敏误伤 <1% ｜公开 repo+threat-model one-pager。

💰 ROI

收紧 trace 侧信道，降低 crown-jewel IP + 凭据暴露面 ｜ traceguard 开源沉淀公开安全资产 ｜ 把"信任面=攻击面"从口号变可度量能力 ｜ data hygiene 永久有效——即便 provider 修补此 CVE，收益不归零。

⚡ 立即行动（本周）
  1. 审计定位：grep agent session stores / journals / SQLite（关键词 thinking/reasoning/signature），画 trace 持久化点清单
  2. 自有表征：取一条自有非敏感 trace，自查 secret/IP token 残留，评估 sibling 解码可行性（限定自有数据）
  3. 立项骨架：起草 threat-model one-pager，开 traceguard public repo 骨架
🚩 诚实挑战（最大风险）：高估了个人风险——该 CVE 主受害者是 provider（被蒸馏的是它们的模型），个人暴露是次级的（trace 内 IP+本地持久化）。窗口可能极短（provider 旋转编码即失效）。"不让 secret 进 CoT"有功能张力（Agent 本就要用凭据推理），故 M3 是"降低概率"非"消除"。成功指标多为 activity 而非 outcome（"未泄露"不可直接测）。须与 credential-manager/PRATA 明确分工，只补"响应内容层"空白带。

④ GEO 提案 — 在 AI 成为发现层的窗口期，锁定品牌引用席位

核心主张：当 AI 搜索成消费者发现品牌主路径，"品牌被 AI 引用且首先被引用"就是新的货架位置——而这个货架此刻无人看守，谁先占位、先建测量闭环，谁就在引用逻辑固化临界点前筑护城河。
连接 GEO 品牌可见性 · 信号 ⚠️(单一来源观点) · 总周期约 6-8 周达成闭环 · 指某零售品牌（脱敏）

🎯 锁定痛点（三个可观测失效模式，全在盲区）

模式表现为何痛
缺席问"买家具哪个品牌好"，AI 答案无本品牌认知归零，且无人知晓
错位被提及但排竞品后，或仅追问才出现首提及份额被锁死
失真被引但信息错误/幻觉（signal 核心警示）信任反噬，比缺席更危险

根因：组织内无人能答"用户在豆包/Kimi 提及本品类，我们是否出现、排第几、说得对不对"——零仪表盘的关键渠道。

📅 里程碑

M1 · 3-5人日基线盲测：5品类×5平台人工矩阵(被引率/位次/准确率/竞品份额)
M2 · 1.5-2周自动化监测：Bun+TS 轮询+标准化 prompt+评分 rubric，周度跑批
M3 · 1周诊断缺口：结构化内容/第三方信源/知识缺口归因
M4 · 2-3周内容投喂干预：结构化内容播种，2 周后重测 delta
M5 · 1周+测量看板+双周复盘+平台版本追踪

📊 成功标准

品牌被引率均值 ≥70% ｜首提及率 ≥40% ｜与 Top1 竞品 SoV 差距 ≤15pp ｜被引准确率 ≥90% ｜监测自动化覆盖 5×5 周度。诚实边界：可观测部分约 20-30%，锚定"趋势可解释"非"完整归因"。

💰 ROI

进攻（moat）：抢占固化前引用席位，占位成本极低 ｜防御（reputation）：早期捕获品牌幻觉/失真 ｜成本：基线仅数人日 ｜方法论可复用外溢。下行有限、上行结构化的早期窗口。

⚡ 立即行动（本周）
  1. 跑一次 5×5 人工基线盲测：5 品类 × {豆包/元宝/Kimi/通义/DeepSeek}，每问 3 轮，记被引/位次/准确/竞品
  2. 冻结 prompt 模板 + 评分 rubric（四维：被引0/1、位次1-N、准确0/1、竞品并列）
  3. 圈定 3 竞品 benchmark + 敲定 5 品类中性问题清单（无品牌诱导）
🚩 诚实挑战（最大风险）："引用率"未必驱动购买（被提及到进店转化因果链未证）；整个品类可能为时尚早（中文 AI 搜索排序逻辑未稳，引用作计量单位未必持久）；signal 为单一社论源含轶事断言；"护城河"假设依赖路径依赖（平台可能随机轮换引用）；5×5 在统计上是轶事。故押注的是"在零可见性渠道建测量闭环此刻成本最低、后悔最小"——即便进攻落空，防御+情报价值仍成立。

⑤ AI 内容溯源 — 把可验证性做成 WellDone 的底层架构

核心主张：在 Google review 生态被 AI 污染、EU AI Act 与 FTC fake-review 法规同步收紧的 12-18 个月窗口内，把 "provenance-first" 做成 WellDone 底层架构而非上线后补丁——事后给既有内容补来源追溯，改造成本是建设期 5-10 倍。
连接 WellDone SaaS / Responsible AI · 信号 Claude 水印+C2PA ✅ · 3 人团队约 10 周

🎯 锁定痛点

#痛点不做 provenance 后果
P1法律暴露：FTC fake-review 单条最高 $50k罚款+平台下架+集体诉讼
P2平台惩罚：Google 反 fake-review + 水印检测review 被过滤、商家降权→客户 churn
P3内部信任断层：AI 洞察无法溯源原始评价产品价值稀释为"不可信摘要"
P4商品化红海：review 采集+AI 回复数十家在做无定价权、CAC 上升

关键洞察：P1-P4 的共同解是同一套数据原语——每条内容都带不可篡改的"来源链"。这不是四个功能，是一个架构。
