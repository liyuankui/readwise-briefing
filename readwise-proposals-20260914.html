① 验证者把关编排层（VGO）

Agent Swarm 工程OpenAI 10K-agent 案例外推
核心主张：万 agent 协同瓶颈不在通信在裁决——生成贵、验证廉、信任锚是机器验证器而非 agent 互信。下一层是 verifier-gated orchestration：从「建信道」转向「建裁判」。

案例解剖（subagent 补充验证的实证数字）

  • 联邦竞速制推断：分组并行探索、唯通过验证的结果才合并；2.7M 消息/88h ≈ 每 agent 每小时仅 3 条——O(n²) 协调被验证器压缩（Latent Space）
  • 生成贵验证廉：88h 出自然语言证明，再 17h Lean 形式化——验证仅占 19% 耗时；成本 $40M / 130B tokens
  • 曾以 100 agents × 50h 预演攻 Euler 问题后转向；另存 Codex 私数据争议（VentureBeat）

里程碑（7 周 · 0.2 FTE）

  • M1（1w）PRATA 协议加 proof 字段：签名 checkpoint 哈希 + 验证报告
  • M2（2w）Life OS 迷你编排器（Bun，<200 行）：subgoal 队列 + 测试绿灯门禁
  • M3（1w）首个 Proactive Agent：选 Done 可 schema 判定的动作
  • M4（1w）审计日志：每 merge 记 agent_id / goal / verdict / 哈希
  • M5（2w）单机 50 agent 压测 8h 无人值守
本周三事：① 写 PRATA proof 字段 RFC（1页）② Bun 原型：subgoal 队列+测试门禁 ③ 定 agent 审计四元组 schema
诚实挑战：OpenAI 未公开架构，以上是外推——胜因可能是模型本身而非编排；$40M 换头条的经济性未证明，个人场景规模差 4 个量级；订单/库存领域多无 Lean 级验证器，可迁移性打折。

② 机器可验判卷轴（Lean-for-Code 折扣版）

评测区分度重建与上周质量惩罚轴合并
核心主张：三模型满分并列非模型同强，而是判卷太软——测试杀不死变异。解法：给质量惩罚轴装上机器可验证据源（变异分数 + 属性测试 + P2P 回归），与 Blast Radius 合成乘法制总分，LLM-judge 降为辅助信号。

类比定界

Lean 验的是二值真值；代码无完整规约，全形式化（Dafny/TLA+/Lean）规约成本以周计不进管道。可进的是折扣版：PIT 变异测试（量化测试集区分度，接入 1 天）· jqwik 属性测试（边界不变量，0.5-1 天/场景）· P2P 回归门（堵 `--tests` 过滤漏回归，0.5 天）。

里程碑

  • M1（2d）满分场景尸检：golden patch 跑 PIT——变异分 <60 证实「测试无区分力」根因；≥80 证伪转攻任务难度（真相时刻）
  • M2（3d）5 场景补 jqwik 属性 + P2P 回归门，场景硬度门槛 ≥70
  • M3（2d）合并公式：总分 = 完成率 × (0.4 + 0.6×质量系数) × Scope 系数，三模型重跑
  • M4（3d）2 repo × 20 cases 人工审对照，一致率 ≥80%
本周三事：① 挑 1 个满分场景跑 PIT，半天出变异分 ② 三模型 patch 互跑「被杀 mutant 数」，免费拿并列初值 ③ 给测试入口加 `--check-regressions`（顺带消掉既有待办）
诚实挑战：若并列根因是任务过易（天花板效应），加严判卷无用——M1 门即证伪开关；变异分高 ≠ 业务正确（必要非充分）；权重 0.4/0.6 是拍的，M4 校准前勿对外引用。

③ 贡献双轨制：机器验证收益，人类自证贡献

人机贡献归属千禧年奖金无主 → 组织计量
核心主张：收益归系统验证（自动台账），贡献归个人归因（证据包）——两轨分离、季度对账。不混计、零自报、可审计。（背景：Navier–Stokes 证明 Lean 能验证「对不对」，答不了「算谁的」——正确性可自动化，归因必须人证）

三层痛点

层痛点
收益层四态台账靠自报、无系统抓手、数字被疑夸大（FY26 三缺口）
晋升层AI 加持后个人贡献无法自证——人人皆 Alpöge：先驱工作恐被工具抢功
制度层无规则则归因即政治：$1M 无主、Tao 斥「目标错位」

里程碑

  • M1（4h）规则 v0.5：四态改自动采集（Jira label + commit trailer），删自报表
  • M2（2 周）Pilot：1 团队 5 人 × 2 sprint，周度 BO 签核
  • M3（1 周）证据包模板（问题定义→编排决策→验证证据）+ Skill Hub 积分打通
  • M4（0.5 天/季）台账 × 证据包交叉对账，出归因报告
本周三事：① 上周四态台账 Proposal 改一页纸「自动采集版」，约 1 位 BO 面谈 30min ② 为 1 位晋升支持候选人按三段式重组证据包 ③ Skill Hub 增「贡献者/使用量」字段，作积分原始数据
诚实挑战：自动采集止于 code/Jira，会议沟通类省时不可计——Lean 有客观裁判，工时没有，台账必有水分只能缩小；FA2 要总收益叙事 vs 工程师要个人荣誉，对账会变成谈判桌；证据包可能激励「为留证而做」的表演性工作。

④ CS336 去留决议 —「数学 AlphaGo 时刻」之后

学习策略决策框架
核心主张：价值非升非降，而是劈裂——AI 接管「造」的底层，手搓复现（kernel 级）贬值；「千禧难题已解」式 hype 陡升，内构地图作为校准器升值。学 LLM 为判断力而非转岗 → 弃生产深度、取校准深度。

四选项

选项投入收益触发条件 → 代价
A 续原契约10h/w×6周全栈+完整作品已被证伪（80h 承诺 0 交付）→ 挤占工作与 CS329Z
B 缩窄模块 ✦荐3h/w内构地图+BS检测器，直喂 Eval 判断力目的=判断力 → 放弃「手搓完整 LLM」叙事
C 换 CS329Z6h/wAgent 编排实操目的=管理 Agent 团队 → 内构空心，遇 AlphaGo 级新闻只能转述不能判断
D 暂停0诚实止损B 跑 3 周仍 0 commit → 判断力外包，学习身份断裂

建议：B，并与 C 组合

CS329Z 主干不变，CS336 降为卫星。理由：① 停滞主因疑为 10h/w 假设本身，续 A 是给同一失败模式续约；② 新闻越猛，越需自持 tokenizer/scaling/RLHF 的「硬度」坐标——Eval 项目要答「模型为何在此失败」，答案在 scaling/data/alignment；③ 编排能力团队有人可做，判断力无处外包——C 不可替代 B，B 可喂 C。

重校准里程碑（10-26 → 12-31，日期驱动改产物驱动）

  • A1 Basics 瘦身留（BPE + attention 白板级讲清）；A2 FlashAttention 砍（读原理半天）；A3 Scaling Laws 留·最高优先；A4 Data 概念留作业砍；A5 Alignment/DPO 留（与治理最相关）
  • 每模块 1 页判断笔记（该信什么/不该信什么/对本组织的含义）；终点 12-31 前发博客《EM 视角：哪些 LLM 内构值得管理者懂》
  • 证伪开关：连续 2 周 0 commit → 自动降级 D，归档写讣告
诚实挑战：B 或是精致的沉没成本辩护——「缩窄」可能只是不敢说「放弃」（对冲：3 周证伪开关，无第二次缩窄）；判断力或根本不需手搓，读+写或已足够（对冲：4 周内笔记只有复述无可校准增量，砍掉动手层）；B+C 双线超载风险（对冲：B 硬封顶 3h/w，冲突时砍 B 保 C）。
