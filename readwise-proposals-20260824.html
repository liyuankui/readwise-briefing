1️⃣ Cloudflare OS 架构借鉴 → OpenMAIC 部署加速

OpenMAIC Cloudflare 🔥✅ Verified~1.5-2 周
核心主张：OpenMAIC 部署的最大风险不是写代码，而是 DO 状态边界、BYOK 网关、沙箱三处设计决策无参照——Cloudflare OS 是同平台（Workers）、同形态（多租户 agent 应用）的官方开源参考实现，把这三处从「自主设计+试错」降维为「裁剪已验证模式」，缩短验证周期 30-40%。

🎯 可抄清单（本地仓核实）

痛点CFOS 可抄物
ClassroomDO 无参照（LangGraph 单进程内存态需重设计状态边界）per-workspace agent = DO per instance 生命周期 + SQLite-backed DO 存储
AI Gateway BYOK：透传/限流/审计（防学生刷爆 key 是刚需）Gatekeeper 代理模式 + 审计日志 + 用量控制
多租户隔离（prompt injection 不外溢）Sandstorm 血统 per-instance 沙箱 + 零信任边界
AI 生成代码执行安全Dynamic Workers 轻量 isolate（先记 skip 档）

🗺️ 里程碑

  • M0 Borrow Map（0.5d）：clone CFOS，must/nice/skip 三档标注
  • M1 Go/No-Go（1d）：OpenNext × Next 16 smoke build + free plan SQLite DO 最小验证
  • M2 ClassroomDO（2-3d）：conversation ledger + WS hibernation + alarm
  • M3 网关（1-2d）：BYOK 透传 + per-classroom 限流（Gatekeeper 简化版）
  • M4 V&V（1-2d）：3 agent × 20 轮 + 30 并发，全程 $0 账单

⚡ 立即行动（本周，~4h）

  1. Clone CFOS + 本地 workerd 跑通（1h）→ borrow-map 骨架
  2. SQLite DO 免费档最小验证（1h）——「纯免费」基石假设，未亲手验证前不假设成立
  3. OpenNext smoke build（2h）+ 真正建出 cloudflare-deployment 分支（侦察发现：intent 有、repo 无，状态漂移）

🚩 诚实挑战

  • 「加速 40%」可能高估：CFOS 没有 Director 调度与 28 动作引擎，可借鉴的只是部署形态层（约占工作量 20-30%）。真实价值是降低设计风险而非缩短工期
  • 为什么不直接部署在 CFOS 上？裸 Workers + 抄模式 > 多一层平台依赖——M0 留 30 分钟验证此结论
  • 最大漏洞是许可证：OpenMAIC 是 AGPL-3.0，二期若对外提供网络服务须开源整个部署——这个决策不做，投入有归零风险
  • 时间账经不起细算：8 月每周真实可投入或仅 4-6h，里程碑心理预期 ×2

2️⃣ 效率收益追踪的「ROI 边界」设计——净值账本

团队效率计划 🔥 新任 Key Owner⚠️ 框架信号
核心主张：效率收益只在 ROI 边界之内兑现——benefit 必须记净值账：毛节省 −「补缝」人力成本，且每份节省的时间必须有可分类去向。只算替代、不算补缝和时间再分配的账，注定系统性高估。

🎯 三重高估机制（去年教训 × 响马框架）

机制证据框架解释
只算毛替代证明潜力，兑现说不清边界之外需人力补缝：AI 输出审核、例外处理、工具维护
吸收无分类「省下去哪了无人追踪」Jevons 悖论：效率↑→工作总量↑而非人力释放
跨项双重计算未追踪A 省的时间变成 B 的缝隙工时，两本账各自好看，净值为零

上周信号佐证：BA 供需趋紧——工程侧省下的时间大概率被需求侧缝隙吸收，正是「更多人补缝」的组织版本。

🧩 设计原则

  • P1 净值：Net = Gross − Gap cost − Run cost（forecast/realized 双口径）
  • P2 边界：声明自动化停在何处、为何再推 ROI 为负——强制思考字段，不设第三硬门槛（尊重「不制造行政门槛」）
  • P3 去向：realized saving 100% 分类：①重部署高价值 ②成本削减 ③填充其他自动化缝隙（防双重计算关键标签）④未解释（风险信号）
  • 净/毛系数：回溯校准的实证折算率，替代拍脑袋的"~50% realization"

⚡ 立即行动（本周 3 件）

  1. 写一页纸 Net Benefit Manifesto：净值公式 + 洗碗机故事 + 净/毛系数提案
  2. 对齐叙事（Sponsor 月会或 async），3 分钟脚本：「去年我们证明了洗碗机能替代 3 个洗碗工。但没人问：谁保养洗碗机？洗碗工的时间去哪了？'50% realization'直觉里差的那一半就藏在这两个问题里。」——争取一句承诺：「今年目标以净值口径设定」
  3. 契约表增补草案：+Gap cost / +Automation boundary 两字段 + Reallocation 分类枚举；请 Backup Owner 各试填 1 个真实 candidate，回收填表耗时

🚩 诚实挑战

  • 餐厅类比 ≠ 知识工作：code review 是补缝还是质量保障？框架不预定义缝隙，由申报者自判 + challenge——它是会计原则，不是物理定律
  • 时机悖论：以「简化工作」为名的计划增加申报字段，本身即讽刺；v1 超过一页纸即算失败
  • 预设放弃条件（可证伪）：若回溯发现净/毛 > 90%（缝隙成本可忽略），简化为纯去向追踪、删成本字段
  • BA 瓶颈的反讽：今年真实成果可能是 capacity 重部署而非 cost down——不提前管理 Sponsor 期望，净值账反而会被责怪「没省到钱」

3️⃣ 本地优先的边界条件修正——M4 Pro 提案 v2（证伪上周结论）

模型选型 / opencode 提案✅ 多源验证
核心主张：凡以省钱为由的本地推理皆错，凡以数据不出域、断网降级、学习实验为由的本地小模型皆对——本地是隐私与玩具的答案，token 经济学的错误答案。

满产对账：双 DGX Spark 全年无休理论满产折 API 收益约 ¥2,543，而 capex ¥57,586 + 年电费 ¥2,811——收益连电费都盖不住。v1 四条隐含假设（装得下/本地省/重量化可用/本地产出即价值）2026-08 全部失效。

🧭 四场景裁决

场景裁决理由
隐私敏感公司数据本地（仅小模型）数据不出域是硬约束；只派摘要/脱敏/分类小任务
日常 agent 循环API（低价档）token 密集、代码非隐私；API 便宜 20-60×
重推理API（旗舰档）24GB 本地根本无此选项
学习实验本地沉没成本，年电费 ¥324，随他折腾

M4 Pro 角色重定义：不是 inference 引擎，是 gateway + 隐私小模型档 + 实验台。

⚡ 立即行动（本周 3 件）

  1. 落盘 v2 至 opencode 提案仓库，v1 四条失效假设标注废止
  2. 建 token 账本：导出各家 API 近 30 天用量，写死「差异 <10%」对照起点
  3. Mac mini 实测 Qwen3-Coder-30B-A3B 4-bit：tok/s + 32k 上下文 KV 占用，判定隐私档上限

🚩 诚实挑战

  • 中国居民电价已复算：电费确实便宜（¥324/年）——但瓶颈从来不是电费，是 capex 摊销 + 满产收益上限 + 重量化质量损失，结论不翻案
  • API 依赖 = 供应/价格风险：三家国内供应商同涨价的尾部风险仍在，届时本地小模型只够降级、不够替代——此敞口接受并留档
  • opencode 提案引用时勿把「API 便宜」说成「永远便宜」——单价长期下行与短期涨价/限量并存
  • 私见：v1 的错不在买了 M4 Pro（gateway 与实验角色照旧），而在让 24GB 干 284B 的活——方案复杂度不得超过问题复杂度

5️⃣ 三人 SaaS 首会议的 AI 杠杆底牌

三人创业项目 🌱 待首会议✅/⚠️ 合成验证
核心主张：三人兼职跑赢 40 人竞品（收 $75/月才活）的方式不是编码更快，而是：harness 化工程系统把 MVP 压到 ≤200 人时（4.5× 压缩），加上 DeepSeek 级推理成本（$0.01/商户/月）让低价档（$19 起）仍有 ~97% 毛利——用成本结构打他们的团队结构。AI 不是噱头功能，是低价的补贴来源。

🎯 痛点倒推（数字验证过）

变量无杠杆有杠杆
MVP 工程量~900 人时~200 人时
交付周期（25h/周）36 周（窗口死亡）8-10 周

兼职热情半衰期 8-12 周——压缩比 <4× 即项目不可行，这是硬门槛不是目标。二级痛点：三人三地，真正瓶颈是决策延迟与上下文不同步。

🧩 杠杆栈 + 成本真相

  • 交付层：Cloudflare Workers + D1 + Pages（MVP 规模近乎 $0）；生产层：单仓 + harness 文档（对 agent、对合伙人同构），人类只写 spec 和 review PR，不写码；运营层：DeepSeek V4-Flash
  • cumora/herdr 只进 watch list 不进栈——成熟度未实测，生产依赖是自杀
  • 评价采集两条腿：请求腿（SMS 短链，MVP 核心，不走 API）；监听腿（GBP API——新项目初始配额常为 0，allowlist 等 2 周+，次日就提申请，MVP 前 4 周不依赖）
  • 成本真相（node 实算）：AI 每商户/月 $0.0107（占定价 0.056%）；1000 商户总 AI 成本 $10.65/月。单位经济学杀手是 SMS（$0.47/商户/月）与获客，不是 AI——做成本模型盯 Twilio 和 CAC，别盯 AI。

⚡ 立即行动（首会前 3 件）

  1. 本文档 + MVP 范围一页纸提前 48h 发合伙人，要求对等交付（渠道测试计划 / 法务 checklist）——把会议从「信息同步」改成「决策现场」
  2. 15 分钟 GBP API 烟测：把「配额风险」从传闻变成实测数据带进会议
  3. 用 harness 花 4-6 工时把 Landing Page + Waitlist 做出来，带 URL 开会——活的 LP 是杠杆的最好证明；若 8 工时做不完，4.5× 神话当场证伪

🚩 诚实挑战

  • 杠杆栈可能是自我感动：AI 压缩的是编码，B2B SaaS 的死活在渠道与留存。若首会议 60 分钟聊架构、10 分钟聊「谁去找前 10 个付费夫妻店」，就是三个工程师的集体舒适区逃逸——技术议题限 20 分钟，渠道打法占一半时间
  • 战略题先于技术栈：「成本领先 vs AI 差异化」不是并列选项——答案大概率是「成本领先为矛，AI 为利润引擎与留存钩子」，但应由三人共谋拍板
  • Kyle 是最大单点风险（每周 10h + 高消耗主业）：harness 文档化的首要受益人应是合伙人，让他们能脱开 Kyle 推进；另需私下确认公司副业/IP 政策
  • 合规红线：禁止 review gating（先私聊满意度再筛人——Google+FTC 双红线）；AI 回复默认草稿模式人工确认，绝不默认全自动
