P1 · 模型供应链完整性三层防线

入册即校验，完整性校验先于行为评测

信号：BadEngram（✅ 参数级）× Terminator（✅ 数据级）× Uber 网关（✅ 工具级）· 连接：AI Security 主线 / eval 线
行为 eval 测不出参数级后门——防线必须建在工件层，并与在途 AI Security 主线同轨而非另起炉灶。

三层统一为「AI 资产入册清单」

层威胁完整性手段
数据级微调集投毒（6000 示例致 20% 失准）来源/许可登记、抽样审计、上线前对照原模型回归
参数级门控后门（2% 参数，干净输入 99.6% 无异常）权重 sha256 登记、下载签名验证、最小权限（沙箱 PoC 承接）
工具级工具供应链来源审批 + 默认禁用 + 令牌交换（tools.yaml 已设计）

衔接：内部安全审计纪律「新代码/依赖先审计」扩展为「新 AI 资产先入册」；credential-manager 管 secrets，入册清单管 AI 资产——同一纪律的两个面。对 eval 线的冲击：新增 Gate 0——自托管/微调模型进评测前先过工件校验，不通过不评；行为分数只对通过 Gate 0 的工件有意义。成功标准：自托管权重 100% 有 sha256 登记；数据集 100% 登记来源；eval 入口 100% 先查 Gate 0；总投入 <1 人周。

⚡ 本周三件事

  1. 模型下载验证脚本（Bun+TS，sha256+官方 checksum 对照，<100 行）
  2. 微调数据集来源登记表（入册清单 v0 数据集页）
  3. eval 流程写入「完整性先于行为评测」原则与 Gate 0

🔴 诚实挑战

  1. BadEngram 是研究演示（14.2M 模型；180B 仅 50.4%）——风险真实但概率未知，按低成本防御定价，不过度反应。
  2. 暴露面不同：API 调用为主 vs 自托管权重——参数级风险主要在自托管/微调场景；API 场景对策是供应商安全条款与审计权。
  3. 清单若变流程税会被影子 IT 绕过：入册操作须 <5 分钟。

P2 · 「要忘掉的更少」——转型优势假说及其应用

转型成败 = 「新手红利 − 老手包袱」净值

信号：Anthropic PM 画像（✅）× FDE 复盘（⚠️ 正文受阻仅开头）· 连接：讲师团 / D1 练级场 / Kyle 自身转型
新手红利 = 无旧流程可依赖；老手陷阱 = 顺从、等结构、不做功课（正是大公司训练的肌肉）——资产与包袱同体，随环境翻转。

三块落地

① 假说验证：包袱量三维（流程依赖度/决策等待度/观点带证率）→ 11 人匿名快照 → 练级场按其分组同题对照，测首交时长——两周无差异即证伪停。② 讲师团 L2-L3「去包袱」：失败模式配对抗练习——

失败模式对抗练习
顺从（VP 说啥做啥）带证据反驳讲师一次，否则不结业
等结构等喂信息删模板删 prompt，裸题交付
只抛热点观点不附三份一手材料不排麦

③ Kyle 自检：每月末用 GOAL_RESTATE「上一级目标」段重答一次；连续三月可复述 →「按年 OKR」警报，强制换上一级。成功标准：高低包袱组首交时长差 ≥30%；对抗练习完成率 ≥80%；连续 3 次重答无一次复述上月。风险：包袱量变相绩效排名（仅自见、聚合匿名）；分组歧视老手（对照即证伪设计）。
