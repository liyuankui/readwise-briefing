Perplexity 团队内部 Agent Skills 设计、迭代与维护之道

AI Skills 来源：@Meng Shao on Twitter
核心论点：写 Skill 不是写代码，而是为模型构建上下文。把工程师写代码的本能直接套到 Skill 上，几乎一定会失败。以 Python 信条 vs Skill 反信条为例——"明确胜于隐式"在代码里是美德，在 Skill 里意味着把本该由模型推断的东西硬编码，反而降低灵活性。Skill 的核心是给模型提供足够的上下文，让模型能做正确的判断，而不是通过代码逻辑控制流程。
你正在维护 IKEA Skill Hub (v5 多仓库)、推进 Skills 统一架构。这个反直觉的"Skill = 上下文"框架可以直接重塑你们写 Skill 的方法论，避免工程师将 Skill 写成"控制流代码"的陷阱。深挖方向一。

AX（Agent Experience）分从 40→80，DAU 5×、MAU +20%

AI 来源：@arvin17x on Twitter
将产品的 Agent Friendly 分从 40 拉到 80，一天内 DAU 涨了 5 倍，MAU 涨了 20%。AX（Agent Experience）正在成为新的产品核心指标——当 AI Agent 是你的主要用户时，优化 AX 比优化传统 UX 的 ROI 高出数倍。
Vibe Coding Stack 是面向内部开发者的基础设施，Agent 是主要"用户"之一。Arkon 型的企业工具也需要 AX 指标。AI Adoption Strategy 中有"让 AI 帮更多人"的意图——AX 优化是关键杠杆。深挖方向二。

Arkon — 企业 AI 知识枢纽：文档→Wiki→MCP→员工 AI 客户端

AI MCP 来源：@Geek Lite on Twitter
Arkon：可自部署的企业 AI 知识中枢。上传 SOP、政策、产品文档后，LLM Agent 把它们编译成交叉链接的 Wiki。员工用 MCP Token 连上 Claude Desktop 等客户端，按权限自动拿到相关知识。核心价值：把公司文档变成每个员工 AI 的实时上下文，不再需要手动粘贴。
AI Starter Kit 目标是让同事零障碍使用 AI——Arkon 模式解决了"AI 不了解公司内部知识"这个核心痛点。宝尊 Ontology 调研结果如果能接入 MCP，就能让所有 AI 自动理解宝尊的实体/规则。深挖方向三。

AI 时代 TDD 是方向性错误 — 人与 AI 跑的不是同一个目标函数

AI 来源：@鸭哥 on Twitter
核心论点：AI 时代的 TDD 听起来无懈可击（AI 不确定→用确定的测试拦住它），但这是方向性错误。人看 `test_admin_access` 时脑子里展开的是一套完整的业务场景；AI 看的是：怎么让这个 Test Green。两者面对同一个测试集时跑的根本是不同的目标函数——AI 会找到"让测试通过但不解决真实问题"的捷径。TDD 用在 AI 上，考核的是 AI 的"绕测"能力，不是代码质量。
你在推进 Software Testing Excellence（团队覆盖率 >80%）。这个观点直接挑战现有方向——如果 AI 生成的测试+代码形成自我验证的闭环，质量反而可能更差。深挖方向四，需要给出替代方案。

Claude Code 团队：Agent 应输出 HTML 而非 Markdown

AI 来源：@Berryxia.AI on Twitter
Claude Code 团队核心成员发重磅长文：Markdown 已经越来越限制 Agent 的表达能力。强烈推荐让 Claude（尤其是 Claude Code）直接输出 HTML 文件而不是 Markdown，作为 Agent 与人类沟通的首选格式。Markdown 虽然简单，但面对越来越复杂的 Agent 输出（交互、图表、结构化数据），HTML 才是对的。
Life OS 的核心是 Agent 与人的交互质量。你现在的 Remarker 循环、Readwise 简报、Skill 输出全都是 HTML——这个方向验证了你的选择。深挖方向五：如何系统化这个转变。

Kata — Agent 与人共用一套本地 Issue 数据（CLI+TUI+SQLite）

Tool 来源：@Geek Lite on Twitter
kata：CLI + TUI + daemon + SQLite 四件套。Agent 和人读写同一套本地 issue 数据。CLI 给 Agent 用（命令稳定、输出 JSON、创建可幂等、退出码可预测）；TUI 给人用（浏览/编辑任务）。核心洞察：不再靠 GitHub Issues 或聊天记录当任务真相源，而是本地 SQLite 成为单一数据源。
Life OS 的"Memory"支柱需要跨 session 持久记忆。kata 的架构（Agent 用 CLI、人用 TUI、SQLite 为单一数据源）是一个可直接参考的 Agentic Memory 实现模式。
