三块落地

#动作衔接既有成果
①沙箱 profile 增会话级快照/回滚原语：每阶段前快照文件+凭证状态；agent 触发全链恢复时验证回滚零残留Seatbelt 管红线，新层管「重来」

③eval-as-gate 立项论据句（第四源）：「分析被压至小时级后，瓶颈转向验证——与 GitHub 审查/Linus/Larson 三源互证」三源 → 四源

里程碑与成功标准

W1 快照/回滚最小 PoC + 多阶段 case V0 草案 → W2 埋错恢复 case 跑通 → W4 双线合流报告。可测：注入假设错误触发恢复后，凭证/文件残留 diff=0 ×10 次；≥1 个多阶段 case 达 V3（每阶段产出机器判分）；第四源句进入 eval-as-gate 立项文档。风险：macOS 回滚原语实现复杂度未探（APFS snapshot vs 文件级 diff）；多阶段判分脚本成本高；封闭工具链结论外推业务代码未验证。

🔴 诚实挑战

  1. 厂商自报，营销偏差大：fast16 八阶段为 SentinelLABS 自测非独立基准；8 小时含多少人工干预未披露。
  2. 场景边界不同：恶意软件逆向是封闭工具链（状态可快照）；业务代码 agent 面对可变代码库与外部服务，recovery 边界需重新证明。
  3. 「瓶颈转向验证」出自防御厂商立场（其卖点正是分析能力，宣称瓶颈在别处对己有利）——采纳为第四源须标注来源立场。
