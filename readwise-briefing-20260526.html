Multi-Agent 系统：生产环境只活下来三种模式
Agent架构Life OSPRATA Yibie · 深度thread
三份独立报告（Cognition/Devin 复盘、Manning 行业报告、metaswarm 开源项目）得出同一结论：
存活模式：1) Pipeline（流水线）2) Orchestration（编排 = map-reduce-manage）3) Generator-Validator（生成-验证）
阵亡模式：对等协作（Agent 互聊、投票、协商）——因"操作携带隐式决策"导致设计哲学冲突 + "级联表面"误差指数放大。
核心洞察：写操作的 Agent 只有一个。多 Agent 解决的不是"更聪明"，是"更便宜+更可靠"。
💡 为什么相关：
① 直接回应昨日 Proposal #2 的架构问题——PRATA 应设计为 Orchestration 模式（管理者单写入），而非对等协作
② Life OS Software Factory 应采用 Pipeline（需求→代码→测试→审查）
③ 昨日 Yetone 问的"多 Agent 协作"问题在这里有了明确答案
④ Generator-Validator 模式 = rubber-duck agent 的理论依据（干净上下文的审查者更聪明）
