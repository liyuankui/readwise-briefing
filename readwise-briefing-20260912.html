D1 · Shopify 从 React Native 回归原生（Swift/Kotlin）

✅ 已核实⚠️ 归因有争议来源：HN 09-11 · shopify.engineering/back-to-native · HN 讨论 · Simon Willison 评
2020 年 all-in React Native 的 Shopify 宣布全面回归原生。核心论据：LLM 编码 agent 改变了「写两遍代码」的经济学，跨平台框架的成本优势被抹平。Shop App 已由 6 名工程师 12 周完成原生重写并上架。
为什么相关：① 这是「AI 改变架构决策线」的最强公开案例——不是 AI 写代码快了多少，而是决策公式本身变了（build vs share、跨平台 vs 原生）。你的 AI 编码评测项目正在测 model×harness，这条信号把评测结论提升到架构选型层面。② 注意 HN 争议：多数原生迁移工作实际发生在 LLM 辅助之前，官方叙事有「事后归因」成分——读官方博客时要分离「事实」与「叙事」。

D3 · 「软件让人疯狂」——软件的无摩擦、无完成态、自我强化

⚠️ 单一来源（随笔）来源：HN 09-11 · graybeard.ing 原文 · HN 452 评论
软件与一切造物不同：想法到实现无自然摩擦（不受物理约束）、没有「完成」的定义（永远可以再改）、复杂性自我强化（优化局部反而恶化整体）。作者称这三条正在让开发组织陷入集体神经症——不是工程问题，是存在主义问题。
为什么相关：FY27「用数字与 AI 系统性简化工作」主线正需要这个框架——技术债讨论中「为什么系统永远做不完」的根因解释。三机制可直接引用进简化主线的叙事：① 加功能无摩擦 → 需人为设立约束（架构守卫）；② 无完成定义 → 需为每个简化项定义 measurable 的 done；③ 复杂性自我强化 → 简化不是一次性项目而是持续对抗。⚠️ 随笔为个人观点，引用时标注来源性质。

D4 · Laravel 禁用 Issue，只收 Pull Request

✅ 已核实来源：周刊 412 封面 · Otwell 原推 · 官方贡献指南 · HN 讨论
维护者宣布：大部分官方包禁用 GitHub Issues，遇到 bug「描述给编码 agent，让它提 PR」。理由：AI 时代提 PR 与提 issue 一样容易，且 PR 附带可运行验证，issue 只是单向索取。Reddit/HN 激辩：贡献门槛是升是降。
为什么相关：内部 Skill 社区（社区驱动、正在做多仓库支持）面临同样的机制设计问题：如何让使用者变成贡献者？「PR-only + AI 辅助」是一个可直接试点的贡献协议——每个 skill 的改进从「留言许愿」变成「带验证的变更」。也呼应你所在团队「所有变更走 PR」的工程纪律。

Bonus · SWE-2 与「benchmaxxing」：TB 2.1 得 92.8%，TB 4 得 27.3%

✅ 已核实来源：HN 09-11 · HN 讨论 · BenchLM
Cognition 发布 SWE-2（Kimi K3 后训练版），Terminal-Bench 2.1 刷到 92.8%，但全新 TB 4 只有 27.3%。社区指出巨大落差 = 对旧版基准的过拟合（benchmaxxing）。另宣称比同类便宜 64%。
为什么相关：你的 AI 编码评测坚持「真实仓库 + 相对比较 + 新任务」而非公开榜——这正是对 benchmaxxing 的结构性防御。此案例是向团队解释「为什么不直接看排行榜选型」的最佳教材：同一模型，换一版基准，分数掉 65 个点。

🏋️ 健身 · 羽毛球：实力差距的本质是「球速对抗」

来源：知乎问答（已抓原文）
预判、反应、击球点决定球速与对手准备时间；主动击球点 = 赢。实操锚点：启动步——对方击球瞬间小跳启动，落地即移动方向；训练用「最低有效剂量」：10-15 秒/组 × 2 组，重神经模式而非体能，练完应精神更好而非更累（避免中枢疲劳）。
行动：下次打球前做 3 项启动步神经训练（侧向/转身/前后各 10-15 秒 × 2）；对打时盯「对手击球瞬间」做小跳。

🧠 健脑 · 庄子：醉汉摔不死的隐喻——松弛 > 紧张
