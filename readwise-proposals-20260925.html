Proposal 1 · AI 味治理：从「经验黑名单」升级为「统计校准体系」

🔬 已亲验 repo 结构主项目：自媒体内容质量总投入 ≤3 工作日

锁定的痛点

关键决策：提炼为主，集成为辅

Proposal 2 · Eval 防过拟合门禁（Anti-Harness-Overfit Guard）

⚠️ 论文归属已纠正：Salesforce 非 Google主项目：AI Coding Eval4 周四层
在 model × harness 选型评测中，harness 本身就是策略的一部分（"unfixed harness → you measure the harness"）；若不隔离评测集与调优输入（held-out 拆分 + harness 冻结 + 泄漏扫描），分数上涨可能只证明"harness 学会了这套题"——防过拟合必须是 pipeline 的门禁，而非事后审计。

锁定的痛点（项目内实证）

  • 96% case 为 judge_only，无 FTP oracle；harness 特有输出风格可能讨好 judge
  • harness 维度仅 1 个 adapter，而选型对象是多家工具；厂商 harness 持续热更新，跨版本不可比
  • 已发生「假 10/10」事故（gpt-5.6-luna，真实 7/10）——未隔离验证的分数会骗人（2026-08-04 修正报告）
  • leak guard 只盖 problem_statement；AGENTS.md/skills 等运行时注入物未扫描

里程碑（4 个，约 4 周）

里程碑内容工时
M1 隔离90 case 分层拆 dev(70)/held-out(20)；report gate 拒其混入2d
M2 冻结harness 版本+配置 hash 写入 manifest；unfixed 数据标"弱信号"2d
M3 泄漏扫描leak guard 扩展至运行时注入物；沙盒快照维持无 git history3d
M4 鲁棒性held-out 复跑 + paraphrase 对照 + judge 双输入 style-bias 检测；产出过拟合系数5d

成功标准 / ROI

  • held-out 与 dev 分差 ≤5pp，超限强制标注"过拟合嫌疑"；manifest harness 指纹覆盖率 100%；人工审与 judge 分歧率较 08-04 事故前降 ≥50%
  • ROI：选型结论驱动 100+ 座位采购；一次错误选型的切换成本远超 4 周 guard 建设。防作弊设计成为 eval-builder skill 的差异化卖点，对齐 UK AISI / NIST CAISI 的 eval integrity 审查趋势

本周行动（3 件）

  • 拆 held-out：90→70/20，更新 report gate（0.5d）
  • manifest schema 加 harness_fingerprint 字段并回填（0.5d）
  • 精读 DarwinX（arXiv:2608.07545），在 research/ 落 signal-verification note——推文归属错误即活教材：二手引用必须回原出处核对
诚实挑战：① 样本量硬伤——n=20 下 5pp 阈值淹没在二项噪声（±~20pp）里，"达标"可能只是没测出来；要么扩 held-out，要么承认它是烟雾报警器而非法庭证据。② 时机质疑——当前仅 1 个 harness adapter，"针对性优化"风险尚未真实出现，先扩 harness 再谈过拟合或更务实；回应：M1/M2 仅 2 天且是扩维后的必需基建——先装门，后进人。③ 结构性盲区——held-out 由同一 judge 评，judge 侧 style bias 不会被拆分防住；真正闭环依赖 FTP repo 落地。本提案降险，不除险。

Proposal 3 · FA2 落地能力标准：把 FDE 能力嵌入现有角色，从项目制变反哺飞轮

✅ 趋势多源验证主项目：FY27 数字简化 / 讲师团季度级
不设新 FDE 岗位，而是显式定义 FDE 能力标准并嵌入现有工程师角色，以「反哺」为验收硬条件：每个落地项目必须把现场 Know-How 沉淀为 Skill Hub 资产——无反哺，不算完成。

锁定的痛点

  • 讲师团断在最后一公里：Survey「高意愿·中能力·低方法论」——课程教 tool usage，不教「现场翻译」（Know-How→Context→Skill），学员回岗仍不会落地
  • 项目制风险：收益框架已产出，但无反哺机制则每个「简化工作」项目都是一次性咨询，「可持续、可采用、可转化」三可落空
  • Skill Hub 飞轮未证：51 skills 中源自真实部署的比例不明——若多来自工程侧想象，商店是货架不是飞轮
  • 转型无阶梯：portfolio 七个 initiative 缺「人的维度」串联

Proposal 4 · 货物/载具双账本：把吴恩达 × DePue 张力变成课程与讲师团的决策操作系统

✅/⚠️ 两极信源主项目：K12 大纲 v04 / 讲师团总投入 ~11h
别赌"编程会不会被取代"。吴恩达说的是载具（编程作为 literacy 必将普及），DePue 说的是货物（写代码的技能溢价必将归零）——同一枚硬币：工具越易得，使用规模越扩、单位溢价越崩。故每课时应标注为「货物」（判断层：定义力/验证/品味，两种未来都升值）或「载具」（执行层：语法/工具流，够用即可，设课时上限），课程由此对两种未来同时稳健。

锁定的痛点

  • 家长转化断层：公理库已答"教什么"，但 v04 每章答不了家长掏钱那句"AI 都会写代码了，这章买的是什么"
  • 讲师 P0 卡在承诺恐惧：候选讲师最大心障是"教的内容三个月后打脸"；没有"哪些敢承诺 12 个月"的分层，教案与招募话术开不了工
  • 个人资产负债表悬挂：CS336 停滞待确认、Rust 未启动，同笔账无判据，每周付决策焦虑的利息

Proposal 5 · S1-Watch：System One 防线（混合象限 + 成本下行情景 + 观察哨）

✅ 昨日新闻已验证主项目：低成本模型选型 / eval 矩阵≤1 人周 · $0
以 ≤1 人周、$0 软件成本，为现有三条线加装"System One 防线"：eval 矩阵补"混合架构"象限、Biz Case 补成本下行情景附录、建月度观察哨——使"国产模型单价低 2-4×"的省钱论证在 agent 架构换代（决策层被 40-400× 便宜的打分模型接管）时不被击穿，且不为天级迭代的新类别付出采购代价。

锁定的痛点

  • Biz Case 假设单薄：省钱论证只比"生成式 LLM 单价"，隐含"所有调用同架构"——评审一句"下代 harness 内置路由，你的单价优势还剩多少？"即可击穿

  • 追踪真空：类别天级迭代（Jev 09-15、CLM 09-24）vs 企业采购周期 2-4 季度——默认结局：落后且不自知
