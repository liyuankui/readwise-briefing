DoorDash Dispatch：调度系统重构✅ 全文已读

11-24 · ByteByteGo（DoorDash 工程博客转述）

动态 VRP（车辆路径问题）调度引擎重构：Coordinator（全局状态/业务规则）与 Compute（无状态计算）解耦，worker 每个 dispatch tick 收 gRPC 自包含的本地化 payload 分片；大规模问题用地理预聚类 + 质心细化 + 全局调和层（补回跨区可拼单订单）；ML 双层 serving——L1 在 worker 内本地 ONNX Runtime 高频评分，L2 远程集群低频重算，另有 multi-agent RL 调优化器权重。替换路径：shadow testing 双跑（新引擎不真正执行）→ switchback 实验（轮流控制真实流量）。数字：处理规模 10×、99.96% 运行 <20s（旧系统峰值分钟级）、超级碗峰值可用性 99.99%+；旧引擎近似二次复杂度、峰值需求达容量 4×。

① 与订单履约域直接同构——门店交易/履约链路的核心权衡正是「慢决策 = 坏决策」（实时状态随延迟失效），Coordinator/Compute 解耦 + 问题地理分解是可直接引用的架构参照。② shadow → switchback 的分层替换验证与 eval 方法论里的分级验证同构：先行为等价、再因果效果——核心链路迁移的标准打法，比一次切换多一层零风险证据。③ 全部关键数字（10×/99.96%/99.99%）为原文自述，采信结构不采信精确值。原文

How I AI: OpenClaw for Executives✅ 全文已读

11-24 · Lenny's Podcast × Ankit Maheshwari（Innovaccer CTO）

CTO 在 Mac Mini 上用开源 OpenClaw 跑自建 AI「首席幕僚」：cron 每 4 小时汇总待批简历（含 GitHub 履历）、Slack 无响应时打电话提醒、点午餐/订餐厅/智能家居。方法论：用 soul 文件定义各代理的性格/边界/权限/路由（比接工具更费功夫）；专家型子代理优于单一通用代理（人设一致性）；护栏明确哪些操作禁止自动执行；代理从纠正中持续学习（咖喱何时配饼）。成本约 $500-600/月（Opus 5.5），本地模型可免费处理摘要/邮件/cron/电话编排。原则：**"1% annoyance"**——任何略烦且重复的任务就自动化。

① 这是「AI 首席幕僚」路线的一手样本，与个人自动化栈（ikit 通知 + 定时简报 + 巡检管道）互为镜像——对方每月 $500-600 换来的经验里，最可搬的是专家子代理拆分与soul 文件化人设/权限两点，正是当前 cron 任务各自内联行为约定的升级方向。② "1% annoyance" 原则给自动化立项提供了可操作的阈值语言，比「值得自动化」的模糊判断好用。③ 全文免费可读，无付费墙损失。原文
