P1 · 练级场重建计划（Judgment Gym）

把「审查 AI 输出」设计成新练级场

信号：@make_claude ×2 · @foxshuo · @chaojidigua · @xingjia520 · @CatChen（6 条 cluster）
Agent 吃掉的不是初级岗位，而是初级长成 senior 的练级场。与其恐慌或禁用工具，不如把「审查 AI 输出」本身设计成新练级场——12 周跑通团队制度，并产品化为讲师团 L3/L4 课程模块。

🎯 锁定痛点：一位初级工程师的一天

入职 8 个月的初级工程师小 A：上午 3 个 bug 全交 Agent，10 分钟出 PR 合并；下午新接口 Agent 写九成，他补一成样板代码；全天零次被 review 挑战、零次独立定位问题。季度绩效写「交付效率高」，但他距「能判断 AI 哪里错」还差上百小时刻意练习——而这些小时正被 Agent 吃掉。

🗺 里程碑（12 周）

阶段时间内容Done 标准
M1W1-2测基线：试点 PR 的 AI 参与率/人工拦截率/盲合并率；制度 v0（AI 审查轮值＋反驳日志）基线报告＋一页纸制度过评审
M2W3-63-5 名初中级试点：每周主审 ≥2 个 AI PR，记录「AI 错在哪」；双周复盘累计 ≥60 条反驳，有效率 ≥50%
M3W7-10产品化：case bank 转讲师团 L3/L4「AI 审查力」模块；提问/验收框架部分由非技术讲师执教，补 P0 缺口模块 v1＋试讲 1 场评分 ≥4/5
M4W11-12对照基线评估，决定是否全团队/跨团队推广数据支撑的决策 memo

📏 成功标准

  • 盲合并率 <5%（对基线）
  • 试点人均 ≥20 条有效反驳（资深复核认定为真 bug/真风险）
  • 试点成员独立定位问题次数较基线 +50%；≥1 名中级能独立主持审查环节
  • case bank ≥60 条入教材

💰 ROI

对冲 senior 产线断供（内部养成成本与确定性优于外招）；练级嵌入日常 PR 零额外课时；盲合并减少降低线上事故风险；case bank 直接回应 survey「低方法论」，讲师团获可持续教材源。

🛡 风险与缓解

风险缓解
效率短期下滑只审高风险 PR；练级 ≤10% 工时
硬挑刺凑数反驳分级（真问题/风格/无效），只计有效
资深被拖成全职教练轮值制，每周 ≤1h，单次 15 分钟
焦虑伤士气定调「投资非惩罚」；外部数据一律标注待核验

⚡ 本周三件事

  1. 拉最近 4 周试点 PR 基线（AI 参与率/拦截率/盲合并率），1 天完成
  2. 约 2-3 名初中级 1:1 各 30 分钟，收集「我抓到 AI 出错」真实案例
  3. 起草审查轮值一页纸制度；讲师团大纲预留 L3/L4 槽位，下周评审

🔴 诚实挑战

  1. 因果未证：「审查 AI」能否长出等价于「亲手写」的判断力无先例证据，可能只练出校对能力。若 12 周有效率持续走低且独立性无变化，按假设失败处理。
  2. 周期错配：判断力以年计，12 周只能证明机制跑通。对上汇报只承诺过程指标，不得宣称「解决 senior 断供」。
  3. 利益错位：组织按季度奖励交付，练级是长期投资；不写入成员成长预期与绩效对话，制度会在第一个 deadline 前死掉。

P2 · macOS 终端 Agent 沙箱评估 PoC

把「Agent 越权读凭据」从 OS 零拦截变为默认拒绝

信号：@ferstar_org（✅ 技术事实）· @lijigang（✅ 旁证）· @dotey（⚠️ 治理类比）
以约 5 人日的对比 PoC，在 Seatbelt profile、容器化、专用 VM 三条路线中选定默认沙箱方案，把「Agent 越权读凭据」从 OS 零拦截变为默认拒绝。

🎯 锁定痛点

深夜长任务，Agent 为「补全上下文」做全盘搜索，顺带读取 ~/.ssh/id_rsa、~/.aws/credentials 与相邻项目，并把摘要写进外发请求。全程无告警（EDR 只见合法子进程）、无审批、无审计——Agent 是继承 shell 全权限的普通子进程。credential-manager 虽已迁 26 项 secrets 入 Keychain，盘面明文残留与相邻目录仍在裸奔。

🗺 三路线假设（PoC 验证对象）

路线隔离强度开发体验维护成本
A：sandbox-exec(Seatbelt)中：syscall 级拦截，无独立文件系统高：原生、秒启高：deprecated、无官方文档
B：Docker/devcontainer中高：FS+网络隔离，共享 VM 内核中：挂载性能损耗低：生态成熟
C：专用 VM（Lima/Apple VZ）高：独立内核与文件系统低：启动慢、同步繁中：镜像与资源维护

🗺 里程碑

  1. M1（0.5d）威胁模型：白名单＝cwd 读写/git/bun/指定端点；红线＝~/.ssh、Keychain、相邻项目、剪贴板、任意出网
  2. M2（2d）三路线各起最小可用沙箱
  3. M3（1d）12 项越权探针 × 3 路线，录拦截率与可观测性
  4. M4（0.5d）三维评分出决策报告
  5. M5（1d）胜出路线封装 wrapper，接入日常 Agent 启动

📏 成功标准

  • 探针矩阵 3×12 结果全满、可复现
  • 胜出路线：红线拦截率 100%；日常工作流（clone/build/test）成功率 ≥90%；启动额外延迟 ≤2s；沙箱配置 ≤100 行入库

💰 ROI

5 人日、零采购；对照一次注入事件的处置成本（轮换全部凭据+溯源+上报）量级悬殊。结论可直接复制为团队 11 名工程师的 Agent 使用规范。

⚡ 本周三件事

  1. 写红线清单＋12 项越权探针脚本（半天，纯本地）
  2. 跑通路线 A 最小验证：读 cwd 放行、读 ~/.ssh 拦截，截图留证
  3. 以假 id_rsa 录一段「现状下 Agent 可任意读」的基线演示，作立项说服材料

🔴 诚实挑战

  1. 路线 A 是在 Apple 未承诺维护的接口上建基建，一次系统更新即可改变行为；须认「最轻但最脆」定位，长期或倒向容器/VM。
  2. 真难点是信任人体工学而非技术：审批多一分，人多一分绕过沙箱的动机——沙箱必须默认无人值守可用，否则注定被弃。
  3. 沙箱压缩的是爆炸半径而非入口：注入仍可在授权目录内作恶，对外表述须克制。

P3 · Eval Pipeline「NL 断言层 + 缓存回放」PoC

确定性下限 + 语义上限，打破双盲排序困境

信号：@vikingmute（⚠️ repo 未定位，机制作自研设计输入）· @lijigang · @mattpocockuk
在现有 eval pipeline 的传统断言之上增设结构化自然语言断言层（llm-as-qa-judge 执行），以 agent 步骤缓存回放支撑判分，用「确定性下限 + 语义上限」双层判分，打破「传统断言满分饱和 × judge-only 噪声」的双盲排序困境。

🎯 锁定痛点

上一轮跑分：某场景 gpt-5.3-codex、haiku-4.5 与国产模型传统断言全部满分——排序失效；改 judge-only 又得 57-59%，样本小无显著差异——排序仍失效。团队日常同样卡在「结果看着对但不达标」：AI 代码能过 JUnit/E2E，人工却能挑出语义缺陷，这层缺陷目前无自动化手段承接。

🧱 分工边界（设计核心）

层职责性质
传统断言编译、既有 JUnit/E2E、回归、风格二值确定性，作 gate，零 flaky 容忍
NL 断言层语义验收：意图符合、边界处理、隐性缺陷rubric 结构化，输出 verdict+证据+置信度
人工低置信度升级件复核、维护金标抽审兜底

铁律：凡能用传统断言表达的验收标准，禁止写成 NL 断言；NL 断言只承接确定性断不掉的部分。

🗺 里程碑（约 11 人日 / 3-4 周，1 名工程师兼职）

  1. M1（2d）断言 schema；从 20 个人审 case 提炼 10 个 case 的 NL 断言+金标
  2. M2（2d）pipeline 产物/轨迹缓存（输出、diff、日志快照+版本号）
  3. M3（3d）接入 llm-as-qa-judge，金标上校准 rubric
  4. M4（3d）小矩阵（2 repo × 2 model）端到端，测一致率/方差/成本
  5. M5（1d）数据报告 + 扩全矩阵 go/no-go

📏 成功标准

  • 金标 20 case：judge 与人审一致率 ≥80%（基线 57-59%）
  • 高置信子集一致率 ≥85%，升级人审率 ≤30%
  • 同输入双判分歧率 ≤10%；回放重判成本 ≤ 全量重跑 5%
  • ≥1 个原满分场景产出非饱和、可排序差异

💰 ROI

人审 20 case/轮 ≈ 7-10 小时 → 只审升级件省约六成；打破饱和 = 选型决策可做（选错模型的迁移成本远超 11 人日 PoC）；沉淀为团队 AI 代码验收层。

🛡 风险与缓解（重点：NL 断言 flaky）

风险缓解
judge 非确定性/flaky只判缓存产物（生成端方差隔离在外）· temperature 0 · 低置信升级人工不硬判 · 双判分歧率>10% 告警
judge 系统性偏见judge 与被评模型异族；每轮金标校准
rubric 过拟合小样本金标滚动扩充+留 holdout
缓存失真快照绑定 harness/model 版本，版本变即失效

⚡ 本周三件事（各 ≤1 天）

  1. 取 10 个已人审 case，各写 3-5 条 NL 断言，标注是否已被传统断言覆盖——边界 spec 初稿即成形
  2. 对既有评分产物双跑 llm-as-qa-judge 测自分歧率——先拿 flaky 基线，再谈建设
  3. 给下次 pipeline 跑分加产物快照落盘——先缓存、后判分，M2 提前启动

🔴 诚实挑战

  1. 57-59% 基线可能意味着瓶颈就在 judge 模型本身：若 rubric+缓存+校准后一致率仍 <70%，本假设证伪。
  2. n=20 无统计力：80% 与 70% 的一致率在此样本量下区分不开；扩金标必扩人审，存在数据成本墙。
  3. 满分饱和也可能源于任务太易而非判分太粗——断言层救不了任务难度，需同步补难任务。

P4 · 模型路由层（magpie 实证）

「agent 订阅」与「模型供给」解耦

信号：@indie_maker_fox · yetone/magpie（✅🔬 README 级亲测，⭐5126，MIT）
以 magpie 本地网关为实证，把「agent 订阅」与「模型供给」解耦，实测国产模型在既有终端工作流的成本与质量，为 opencode-proposal 与国产工具试点 Biz Case 补上「模型路由层」论据。

🎯 锁定痛点

一台 macOS 并存多个终端 agent（订阅制 + API key 混用）。想在某个 agent 换用 DeepSeek/GLM，须手工改其配置文件（model/provider/key 三处），一处写错整段失效；配额烧尽再手工换号。成本侧：国产模型单价约为 Copilot 托管模型的 1/2-1/4，但缺同工作流下两类模型的可比数据，提案说服力不足。

🗺 里程碑（个人 → 团队 → 提案）

阶段内容估时
M1 个人试用个人设备装 magpie：≥2 agent × ≥2 国产模型，记录配置、切换、配额漂移3 天
M2 个人评测接入既有 Eval 框架：同任务集跑「原生 vs 路由国产」，出成本/质量对比1 周
M3 合规边界与安全/合规确认：公司设备装本地网关的许可、BYO-key 政策、数据路径1-2 周（并行）
M4 团队小样获书面放行后，3-5 名志愿工程师试用 2 周 + survey2 周
M5 提案沉淀「订阅×模型解耦」写入 opencode-proposal F2-F5 与 Biz Case 成本章节3 天

📏 成功标准

  • M1：路由跑通，模型切换 <1 分钟，配置注释与格式无损
  • M2：成本对比数据成表（目标降幅 ≥50%），质量损失有量化边界
  • M4：≥70% 试用者愿继续用，周均主动切换 ≥3 次
  • M5：路由层论据被正式提案与 Biz Case 引用

💰 ROI

个人：多 agent 重复配置由每次 15-30 分钟降至分钟级。团队（12 人外推）：若 30% 日常任务可迁移国产模型，按 2-4× 单价差，token 支出约降 15-30%（保守口径）。谈判：证明订阅与模型供给可分离，采购可按模型单价单独比价——此杠杆认知价值大于直接省钱。

🛡 风险与缓解（只论边界，不给绕过）

风险边界与缓解
公司设备装个人网关的许可试用期仅限个人设备；上公司设备须 IT/安全书面放行
BYO-key 合规个人 key 能否触公司代码须明文规定；未确认 = 公司代码只走已批准通道
数据路径验证流量仅经本机、无遥测（README 审查 + 抓包）
供应链社区项目仅当实证工具、不当采购项

⚡ 本周三件事

  1. 个人 Mac 跑通「订阅 agent → 国产模型」最小路由，留证
  2. 网关许可与 BYO-key 两个边界问题以问询形式发安全/合规（非安装申请）
  3. Eval 框架加「路由 vs 原生」任务集，定成本/质量指标

🔴 诚实挑战

  1. magpie 只改善「换模型」的体验，不改变模型能力：若国产模型在真实编码任务上质量差距大，路由层只是切换更快，不自动省钱——M2 须先证质量，再谈成本。
  2. 部分订阅协议禁止第三方代理调用，「解耦」与订阅条款的冲突须 M3 一并确认；厂商或以条款收紧反推捆绑价格。

P5 · 好问题工作流（Question Quality Loop）

把「问题质量」变成可度量、可复利的基础设施

信号：@python_xxt（✅ 一手体验）· @lijigang · @poteto · @uudonX（⚠️ 二手）· @Morris_LT（⚠️ 单源叙事）
AI 执行力已充裕，瓶颈上移到「问出有价值的问题」。本提案将两个提问 prompt 与一条 AI 输出阅读纪律嵌入每周回顾与意图提案制，使「问题质量」成为 Life OS 内可度量、可复利的基础设施。

🎯 锁定痛点

某周例行回顾的真实场景：意图清单躺着 20+ 条活跃意图，AI 提案不断堆叠，但多数是「AI 能做什么」的排列，而非「我最想发生什么」的澄清——没人问过「这条意图背后，是否有我一直绕着走、没真正问出来的问题」。回顾退化为状态同步：意图被维护，未被深化。同一周，Agent 产出的提案/周报/diff 还需逐字读，回顾时间被阅读吞掉，留给思考的所剩无几。

🗺 里程碑（共约 4 个工作日，跨 4-6 周）

#里程碑产出估算
M1Prompt 资产化prompt 库新增 DEEP_QUESTION.md、GOAL_RESTATE.md（原文＋适用边界）0.5 天
M2回顾流程升级回顾模板加两环：深问（每次挑 3 条意图）、目标复述（AI 复述，本人书面修正）1 天
M3阅读纪律落地AI 输出分级：TL;DR＋决策点必读，过程叙述可跳过1 天
M4度量闭环先测 2 周基线，再建问题质量记分卡＋深问日志1 天
M5四周复盘数据评审，决定是否纳入讲师团 L0-L4 方法论0.5 天

📏 成功标准

  • 4 周内 ≥50% 活跃意图经 goal-restate 校验并留痕
  • 深问日志 ≥4 条：每周显式化 ≥1 个「绕着走的问题」（无发现也记「无」）
  • 提案一次通过率较基线 +20%；单次回顾阅读 Agent 输出耗时 −30%

💰 ROI

回顾约 2h→1.5h；意图从「被维护」变「被深化」；沉淀「教人向 AI 提问」方法论补入 L0-L4 课程（一次投入双产出）；长期对冲「AI 越强、人越弱于提问」的结构性风险。

🛡 风险与缓解

风险缓解
深问环节流程化空转无新发现记「无」；连续 4 周无真实改写即撤除
AI 复述制造「被理解幻觉」复述后本人必须书面确认/修正一次

⚡ 本周三件事
