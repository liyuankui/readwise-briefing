黎曼猜想 Lean 证明通过形式化验证✅ 多源外部核验

11-27 · 知乎讨论（外部核验：Lean Prover 官方博客 · MIT 验证文件页 · Forbes 11-24 · Lean FRO + Mathlib 联合声明）

Levent Alpöge（Anthropic 数学家，与 Claude 协作）11-20 发布的黎曼猜想 Lean 证明（约 1700 万行代码）已通过独立形式化验证：Lean FRO 与 Mathlib Initiative 发联合声明确认核验完成；两套独立工具确认所证定理与 Mathlib 中黎曼猜想的规范表述完全一致（排除「证了个别的命题」）；验证文件公开于 MIT 服务器供复检。

Introducing: Langfuse Topics✅ 全文已读

11-27 · langfuse.com 官方公告（公测）

把生产 traces 自动聚类成带名称的主题，回答「用户拿我的 agent 做什么、在哪里失败」。四内置 facet：Intent / Sentiment / Outcome / Issues 分别聚类（同一问题跨 Intent 只形成一个 Issues 主题）；live maps 持续扫描 + snapshots 一次性对比分析；四步原理（低成本模型摘要 → 聚类 → 强模型命名 → 增量刷新）。定位：发现「未知的未知」→ 再据此设新 evaluator——官方自案例：发现 Halo 被用于写作业、被渗透测试。开源可 self-host（v4），模型走自己的 key，测试过日百万级 traces。

① 与 eval 方法论主线直接互补：evals 管「已知问题的回归」，Topics 管「未知模式的发现」——两者闭环正是「分层验证」缺的那半边（生产流量侧的自动分诊），OTel 调试线（11-15）的工具图又补一块。② 官方案例本身就是 agent 上线后的真实风险清单（滥用/渗透/不可见 reasoning），对讲师团 agent 安全小节是好素材。③ billable unit 按 facet 摘要计费 + 模型走自己的 key，成本结构清晰，试用门槛低。原文
