Proposal 1: my-skill-evolver 算法升级

Skill Hub my-skill-evolver SkillOpt 论文
保留 harness 思路，但升级为"有验证集、学习率、负样本记忆、可复现日志的外部状态训练系统"。引入 5 个算法部件。

5 个算法升级

部件作用参数
独立 optimizer model只负责读 trace + 产出 patch，不执行不评分三角色分离
三段式评测集train/val/holdout 门控只有 val 提升才 accept
文本学习率限制每步变更量4-8 ops/步最佳
Rejected buffer失败 patch 存档 + 去重降权同类失败↓50%
Slow meta-update每 N 轮跨 skill 沉淀成功模式周期性 consolidation

里程碑

阶段时间产出
M1 Benchmark schema3-4天cases + score vector + train/val/holdout + manifest
M2 Patch Optimizer4-5天patch DSL (add/del/replace) + 4-8 ops budget
M3 Validation Gate4-5天独立 evaluator + rejected buffer
M4 Slow Memory + Pilot1-2周3 skill pilot → 扩展到 10 高频 skill

成功标准

  • Pilot skill held-out 分数提升 +8pt
  • Patch 接受率 10-30%（太高=门松，太低=搜索差）
  • 同类失败 patch 再现率下降 50%
  • 最终有效版本只含 1-4 个核心 accepted modifications

⚡ 立即行动

  1. 定义 evolution-manifest.json：skill sha、dataset version、judge version、score、accept/reject reason
  2. 实现 patch DSL + op budget：每步最多 8 ops，不再自由重写
  3. 选 1 个 pilot skill 建 train/val/holdout v0（推荐格式明确、可自动评分的 skill）

🔴 诚实挑战

真正难的不是 optimizer 而是 benchmark。没有好评测，优化只会放大噪声。且一旦做成，维护对象从"skill 文本"变成"skill + benchmark + memory"——更强但不更轻。

Proposal 4: Harness Runtime 统一基础设施

Life OS Trust & Eval SkillOpt harness 验证
把分散在 5 个 skill 里的"定义→执行→评估→接受/拒绝→迭代"回路抽成可插拔的 Harness Runtime，让任何 Agent 输出都能被统一训练、验证、记忆与收敛。

架构轮廓：5 个共享层

层职责
Harness Contract目标、约束、成功标准、预算、终止条件
Execution Engine统一状态机：Plan→Act→Eval→Decide→Learn
Evidence Storerun/trace/评估结果/rejected edits/accepted patterns
Policy Layer学习率预算、重试策略、reject buffer、meta-update
Skill Adapters各 skill 只保留领域特有部分

里程碑

阶段时间产出
M1 定义协议1周状态机 + artifact schema + budget model
M2 双试点2周my-skill-evolver + delivery-closure 接入同一 runtime
M3 三大机制2周learning-rate + rejected buffer + weekly meta
M4 扩展1周接入 project-harness + bdd-testing

成功标准

  • 4 个 skill 接入，重复 eval 逻辑减少 ≥60%
  • 新 skill 接入时间从天级降到 半天内
  • 重复失败 4 周内下降 ≥40%
  • 100% 运行有可追溯 artifact

⚡ 立即行动

  1. 写 RFC：Harness Runtime v0.1 状态机 + artifact schema + 三机制
  2. 选双试点：my-skill-evolver（训练型）+ delivery-closure（验收型）
  3. 先做最小共享层：run record + reject buffer + pass/fail evidence

🔴 诚实挑战

最大风险不是技术而是纪律：如果后续新 skill 仍偷偷自带 bespoke loop，runtime 会沦为"又一个 skill"。成功条件只有一个：今后所有需改进的 Agent 输出，默认先接 Harness Runtime。
