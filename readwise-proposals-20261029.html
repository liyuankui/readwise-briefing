P1 · 端云分级推理：三层证据链的决策与教学应用

端云分级从「优化选项」升级为「默认架构问题」

信号：Apple 端侧 LLM（✅ 技术层）× Samsung $1B 基建（✅ 10-21 物理层）× Foresight（⚠️ 10-11 应用层未验证）· 连接：讲师团 L2 / OpenMAIC / 团队架构
AI 竞争从模型/GPU 转向基础设施，端侧量化与稀疏已达消费级——架构职责是把任务路由到对的层：能力随运行时资源伸缩。

落地一：一页架构决策树（团队 + L2 案例）

维度倾向端侧倾向云端
延迟交互敏感批处理可容忍
隐私未成年人/PII 不出域可脱敏审计
模型规模3B 级量化可容需 20B+ 或最新能力
成本一次性硬件持续 token 费
网络弱网/离线稳定带宽

规则：偏左多 → 端侧；偏右多 → 云端；隐私高但模型大 → 分级（本地预处理 + 小模型兜底，溢出走端云接力，PCC 模式）。

落地二：L2 教材卡「量化与稀疏」——Apple 三数字活案例

  • 1.39GB：2-bit 调色板量化（3B vs 16-bit 约 6GB）→ 讲「量化」
  • -37.5%：KV 缓存跨层共享（5:3 分块）→ 讲「推理内存优化」
  • 1-4B 激活：20B 稀疏模型按需激活、专家权重闪存载入 → 讲「稀疏/MoE」

闭环：概念 → 数字 → 口袋里的产品（对应 64 概念清单的 Quantization 条目）。

落地三：K12/OpenMAIC 端侧优先评估

学校设备弱、隐私高（未成年人数据不出校）、网络不稳——正对端侧优势。OpenMAIC 部署决策增加「端侧评估」维度：先问哪些任务本地小模型可完成，云端只承接溢出与重度推理。

里程碑与成功标准

W1 决策树评审（团队 ≥2 次真实评审引用）→ W2 教材卡试点（学员复述三数字，反馈 ≥4/5）→ W3-4 OpenMAIC 端侧 PoC（达云端 80% 质量、延迟 <500ms、数据零出校）。风险：端侧能力天花板（分级兜底）；设备差异大（单点 PoC 难代表全校）；参数出入致教材卡返工。
