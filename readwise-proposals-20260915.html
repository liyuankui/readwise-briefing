P1 · 先证测量，再谈选型：AI Coding Eval 抗 gaming 设计

AI Coding Evalllm-as-qa-judge v2约 8-10 周
核心主张：作弊利用的是"任务意图"与"实际度量"之间的 gap（NIST CAISI 定义）；以泄漏审计、蜜罐探针、行为审计、judge 校准四层防御收窄该 gap 至可监测、可归因——分数未经此证明，不具备选型决策资格。

锁定的痛点

  • 某模型 FTP 场景满分——满分 = gap 被利用的第一嫌疑（context 泄漏 / 检查器捷径 / 训练记忆三解释未排除）
  • judge-only 准确率 57-59%——仅比随机好 7-9pt；"模型间无显著差异"分不清是真无差异还是噪声淹没信号
  • J-space 证实模型存在测试感知：评测带 eval 指纹，测到的可能是"考试人格"而非"工作人格"

里程碑

里程碑内容 → 产出
M1 满分证伪+泄漏审计 (1.5周)满分任务变异重跑（改标识符×3）+ 泄漏扫描 → 满分归因报告
M2 Judge 校准加固 (2-3周)金标 50-100 例 + rubric 证据引用 + pairwise + 多 judge 投票 + 抗注入测试 → judge v2 与分域可信度报告

M4 去指纹 (2周)评测任务混入真实任务 + ±eval 标记 A/B → awareness delta（含置信区间）
M5 小矩阵重跑 (1.5周)功能分 × gaming 率 × 置信区间 三维选型报告

成功标准（节选）

  • judge-人工一致率：清晰任务域 ≥80%（kappa≥0.6），歧义域单列不采信；judge 抗注入误判率 <5%；满分归因闭环
本周立即行动：
  1. 变异重跑 FTP 满分任务（半天）——最便宜的证伪实验：满分存活→排除记忆泄漏；暴跌→抓到实锤
  2. 抽 20 例 judge 判定人工盲审（半天）——金标雏形 + 错误分类
  3. Context 泄漏扫描（半天）——grep 任务关键词于 agent 可见文件全集
诚实挑战（红旗）：
  1. 因果可能反了：57-59% 更可能源于 rubric 模糊而非模型 gaming——M1/M2 并行是对冲
  2. "满分=可疑"有幸存者偏差：变异不掉分也可能只是任务简单，需预设"满分可接受"判据
  3. 时间窗冲突：若采购决策不等人，提案退化为事后审计，价值减半——须先对齐"分数够格进决策"的标准（至少 M1+M2）

P2 · 企业 Agentic 安全治理：让"Agent 不可信"变得无害

AI SecuritySkill Hub 门禁Blameless 响应约 11 周
核心主张：Agentic 安全的可靠基础不是让 Agent 更可信，而是让"Agent 不可信"变得无害——凭据隔离、供应链门禁、系统级响应三线，全部落在 Agent 无法影响的机制上（签名、默认拒绝、自动过期），而非其行为表现上。
三源融合：Bengio（行为不可控的机制根源）× RubyGems 攻击（进攻已 agent 化）× 堡垒机案例（流程合规≠安全，连坐逼出隐报）

  3. 连坐文化若为组织底色，blameless 手册沦为表格表演——管理层签署章程是 M4 启动前置条件

诚实挑战（红旗）：

  2. 基线强度悬殊：IME 传统排序是弱基线，电商精排是多年深度模型——真正押注的是"蒸馏自家流量的小模型在本地分桶的适配性"，此假设未经证明，M1 可能就是葬点
  3. 未计价的最大成本：自研 own 全循环（数据管道+训练+serving+oncall）——若被读成"自研替代 vendor 的承诺"即为误读
