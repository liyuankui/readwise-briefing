Shipping 100+ PRs to Production in a Week✅ 全文已读

11-26 · Will Larson（lethain.com）· Imprint 金融科技公司实战复盘

生产级金融系统单周最高 115 合并 PR（最佳 7 天窗口 170，其中 ~150 个持续部署到生产），每工程师每周 PR 数一年提升约 50 倍。核心论点：生产力提升 = 持续优化同一个开发循环，每次跃升都来自解决一个新瓶颈，而瓶颈会不断转移。2026 年瓶颈时间线：CI/CD 现代化+feature flag → 知识库纠错/配置入仓 → Jira→Linear → 云端 fleet harness（脱离笔记本、事件触发、内置 MCP）→ 内部 MCP 提议变更+按角色审批 → PR 快速通道 → 验证模式评审（审阅验证文件决定是否细审） → 事件驱动工作源（安全发现/错误日志/客服反馈）→ `/my-open-work` 每日编排技能。当前三大未解瓶颈：困难工作提速、验证覆盖率、全自动编排。作者态度：质疑「CI/CD 已死/代码评审已死」——高合规场景仍必要；"merged PRs per week is just a number that asks questions, not answers"；"I suspect everything we are doing today is long-term wrong"。

① 这是 FY27 效率主线迄今最完整的一手参照系：瓶颈转移方法论（5→20→40→80-100 的每一跳都归因到一个具体瓶颈+解法+时间点）正是跨台账收益框架想要的「可验证的效率叙事」样板——且作者的指标观（吞吐量是提问不是答案）与收益验证纪律同构，先立框架再谈数字。② 「审阅验证文件决定是否细审」= 验证文件双轨的行业级实践——用机器生成的验证证据分流人工评审注意力，与 eval 分级验证/分层审查 v2 是同一设计，多了一个生产规模（金融合规场景）的实证。③ 讲师团 AI Upskill 的最新案例素材：不是 AI 原生公司、在既有流程上逐步改造的路径对传统团队更有迁移性；DORA 2025「AI 放大既有优劣势而非自动修复低效」与此互证。原文

Great Engineering Managers Create Business Value✅ 全文已读

11-26 · techscoop.substack

"Building software successfully is not the same as building successful software"——技术卓越本身无法证明投资合理。四层工程领导力框架（技术执行 → 客户问题解决 → 商业机会发现 → 商业价值创造，成反馈循环）。EM 区别于 IC 的三种能力：区分请求与需求（客户要仪表盘，真实问题是手工对账耗时）、机会成本思维（build/buy 基于竞争差异化而非技术偏好）、商业翻译（不说「迁移了缓存架构」，说响应时间/增长支撑/峰值体验并对照预期报告实测）。数据：McKinsey 2024 高效 IT 组织收入增长多 35%/利润率高 10%（相关性）；云优化 $25K/月 → 年化净收益 $220K；DORA 2025 AI 放大既有优劣势。

① 「商业翻译」正是跨台账收益框架的表达层——把工程改进翻译成经济结果、对照预期报告实测，这个句式可直接用于向上沟通与 FA2 收益叙事，与「IAT 是技术债护栏」的量化逻辑互补。② 单指标激励扭曲（只奖吞吐→低影响力功能；只奖可用性→不敢发布）给团队度量设计提供了一张现成的反面清单，与 Larson 文的「指标是提问不是答案」同一天互证。原文
