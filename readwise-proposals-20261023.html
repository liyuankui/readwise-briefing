P1 · 分层审查 v2：三源合流

策略人定、条件机器判、人只守高危/抽样/练级

信号：Will Larson: Speeding Up Code Review With small-change（✅ 全文）× P1 路由（10-17 GitHub Copilot）× D1 轮值（10-06 立项）· 连接：练级场 / Linus 标注提案 / L1 gate
审查从人工轮值升级为三层模型——策略人定、条件机器判、人只守高危/抽样/练级。Larson 数据（事故 -42%/严重 -78%）证质量与速度非权衡，前提是 CI 判定条件。

锁定痛点

① 审查 p50 膨胀（Larson 场景 33→77 分钟），Copilot 评论后轮值者趋转发器；② P1 只答「审多深」未答「何时可不审」；③ D1 全人工排班，练级效果不可量化。

一、三源对照 → 统一模型

维度LarsonP1 路由D1 轮值
解决审查排队膨胀AI 后注意力上移审查即练级
机制CI 判条件免深审路径路由人工排班
缺不承载成长无免审、无作者维度无机器判定

统一 v2：机器判——行数、路径、影响服务数、AI 无 p1/p2、作者按服务合并数；人设——路径分级（资金/共享库）、阈值、抽审率、季度调参。

二、.small_change 草案（先严后宽）

max_lines: 400        # Larson 1000，我们先严
ai_review: no_p1_p2
merges_in_service: 5  # Larson 10+，11 人团队从 5 起
services_touched: 1
exclude: [payment/**, shared-libs/**, workflows/**]
audit_sampling: 0.10  # 仍抽 10% 人审

按服务 5+ 且 90 天无 revert，季度上调。

三、经验值即授权（练级场闭环钥匙）

练级场 PR 累计按服务经验值，达阈值解锁 fast-lane：练级 → 兑换审查信任 → 轮值名额转高危影子审查——练级场的产出第一次有了可兑换的硬通货。Linus 标注（AI:none/assist/pair/gen）随行调审深度。

四、防退化：meat proxy 检查

① 只裁决不改写，禁照抄 approve；② 监控纯转发占比（审查耗时 ≈ AI 输出即告警）；③ 审计者月抽 5 个免审 PR 防橡皮图章。

里程碑与成功标准

W1 定 1 试点服务 → W2-4 shadow 试跑 → M2 全团队试行 → M3 经验值闭环。可测：符合率 ≥8%；免审通道 revert 率 ≤ 常规基线；高危人审 p50 不升；抽审漏检率 <2%；纯转发占比 <10%。ROI：月 200PR × 10% × 1h ≈ 20h 投高危练级。风险：阈值过松（抽审兜底）；数据冷启动（shadow 先行）；AI 判 p1/p2 不稳（先校准）。

⚡ 本周三件事

  1. yaml v0 选 1 服务 shadow 试跑
  2. 导近 6 月按服务合并数据验 5+ 覆盖率
  3. 轮值表加转发率列，对齐 Linus 标注

🔴 诚实挑战

  1. 数据不可照搬：10% 符合率与 42%/78% 降幅出自 Larson 公司场景（大规模成熟 CI），11 人团队 PR 分布不同——只作假设，须 shadow 实测。
  2. 免深审 vs 练级场的张力：低风险 PR 既是练级材料也是免审首选——练级场 PR 例外留人审 + 重心移向高危影子审查，损 fast-lane 收益，系刻意交换。
  3. 经验值固化不平等：只数次数奖励多提交而非好提交，需叠加 revert 率，否则成资历壁垒。
