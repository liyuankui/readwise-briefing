P1 · Salesforce 五铁律注入三在途项目

Prompt 只能塑造行为，代码才能强制规则

信号：Salesforce Agent 技术栈深潜（✅ ByteByteGo 转述）· 连接：讲师团 L3 / 谄媚防护 / eval+简报成本线
可判定规则下沉为代码 gate，上下文按任务精选，L3 缺口顺势补上——五铁律一次注入三个在途项目。

L3 骨架：五铁律 × 正反案例

铁律反面案例我们场景正面设计
弃单一大 prompt（>8 条指令被忽略）千行塞 30 条规则，选择性失忆下单校验前置 guard 代码，LLM 只管意图
ACE 精选上下文 124k→9k全量目录塞窗口，命中被稀释检索前置 top-k 切片，按场景精选字段
Agent 独立身份令牌共用个人账号，越权难追责service account + 最小权限 RBAC + 审计
MCP 只暴露 4 工具40 工具全挂，选错与膨胀齐涨按任务分组挂载，单会话 ≤4 个
塑造 ≠ 强制prompt 写「禁止退款」仍被话术绕过退款闸门放代码层，prompt 只管语气

三块落地

① L3 一课（上表即骨架，每铁律 15min 正反对照+代码现场演示）；② 三指令改写（可判定者降为代码 gate：越权→权限 gate；不确定→引用检验器抽检；谄媚→测试集进 CI 违例即红——prompt 语句数减 ≥1/3）；③ 成本线（盘点两条管道长上下文逐项裁剪，先 V0 快速环验证）。成功标准可测：L3 学员测验 ≥80 分；谄媚 gate 拦截率 100%；eval 单次 token 降 ≥50% 且分数漂移 ≤2%。

⚡ 本周三件事

  1. 回源核对原博；8 条阈值自测（3 模型 × 10/20 条指令消融）
  2. 三指令逐条标注 prompt 塑造 / 代码 gate，出判定表
  3. 统计两条管道 token 基线，圈出 top-3 长上下文

🔴 诚实挑战

  1. 8 条指令阈值是 Salesforce 场景经验值，模型代际差异大，须自测后采用。
  2. 93% 压缩依赖其自建 ACE 基建，我方无等价检索层，比例不可照搬。

P2 · 「AI 红队攻击链」注入安全与 eval 双线

攻防镜像 → 「链式推理任务」评测家族

信号：Rubrik Code Guardian（✅ 私有预览，方法论参考）· 连接：SentinelOne 深挖 / 沙箱快照提案 / 安全团队协作
借 Rubrik 的方法论而非产品：统一「攻（攻击链发现）/ 防（SentinelOne 防御链恢复）/ 评（多阶段埋错 eval）」为链式推理任务家族；「隔离副本跑红队」成为沙箱原语的首个真实业务场景；作为与安全团队联合立项的切入案例。

① 链式推理任务评测家族（统一进 V3）

任务方向链结构度量
攻击链发现红N 弱漏洞 → 路径 → 可利用性验证链完成率 / 误报
防御链恢复蓝多阶段埋错 → 定位 → 修复恢复率 / 定位步数
交叉红+蓝红队产出埋给蓝队双向成本

② 沙箱线的最佳用例

红队 agent 需要全库读访问 + 攻击链验证涉及危险写/执行——恰是 Seatbelt 红线 + 快照/回滚的真实需求（分析跑在隔离副本，破坏性验证可回滚）。比恶意软件分析更贴代码库场景，直接补强沙箱提案的「为什么需要」。

③ 安全团队协作切入点

话术：「不造轮子，评估业界方向」——Rubrik 已公开验证方向（预览版，评估而非采购）；我们出沙箱隔离技术 + eval 方法论，他们出威胁模型 + 业务影响排序 + 合规边界；产出 PoC 评估报告（做/不做/等多久）。里程碑：W1 方法论清单 + 沙箱提案补红队用例段 → W2 任务族 spec + 2 个可运行 V3 样例 → W4 安全团队 30 分钟分享。成功标准：spec 覆盖攻防双向且样例可运行；沙箱每条原语有红队场景映射；安全团队给出「同意评估」或「明确拒绝+理由」任一（皆闭环）。

⚡ 本周三件事

  1. 沙箱提案补「红队用例」段（快照/回滚映射）
  2. 一页 spec：链式推理任务族（攻/防/交叉）
  3. 约安全团队 30 分钟，讲 Rubrik 方法论案例

🔴 诚实挑战

  1. 厂商预览版无独立验证：无误报率与成本数据——案例价值在方法论（隔离+串联+验证），不在产品选型，对外表述须如此限定。
  2. 攻击链串联对代码库规模强依赖：中小仓库效果未必迁移到中大型 Java 单体仓——PoC 须用真实仓库切片，不得以演示结论外推。
  3. 全库推理成本未公开，高频运行或不可行，先按需触发。
