Proposal #1 · Life OS 🔥 微信情报底座

微信群情报底座：48 小时对比选型（架构层）

核心主张：不做二选一，做分层解耦——采集层借壳（离网留存、适配器隔离、可换可抛），管道层自有（Bun/TS ≤500 行，四步闭环升格为多源接口）。48h 只回答一个实证问题：微信解密链路今天能否在本机跑通；跑不通则先以零风险源（HN/Reddit）验证多源合同，微信最后接入。

📋 事实基线（当日亲测复验）

  • A · wechat-intelligence-hub：情报应用层，AGPL+商业双许可，创建 2 天已 393→959⭐/973 fork，DMCA 脆弱性高
  • B · signal-vaults：信号管道层，Apache-2.0，48⭐/54 fork，sources 可插拔架构，HN/Reddit 源零微信依赖可独立存活

🚩 里程碑

  • M0（今天 30min）：两 repo 离网镜像至 private——GitHub fork 不防 DMCA（网络级连带下架）
  • M1（2h）：零微信评测——B 的 doctor/hn/reddit 端到端 + A quickstart，评分表 ≥7 维
  • M2（≤4h）：微信链路 spike——DB 副本上解密，调试 2h 上限，超时降级（降级≠失败）
  • M3（1.5h）：决策树走查 → 1 页 ADR（a 采用 / b 自研 / c 借壳+自有管道）
  • M4（stretch）：TS SourceAdapter 接口 + 双源单命令简报

📏 成功标准

  • 48h 内 ADR 定稿且每维附证据；微信链路得二值结论（跑通或降级均算达成）；隐私红线：出口审计确认无明文聊天数据离机

⚡ 立即行动（本周）

  • 今天：M0 离网镜像（唯一「不做即失效」项）→ 周内晚：M1 → 周末：M2+M3，结果回填 Life OS 意图
诚实挑战：「两日相继爆红=窗口期」是叙事偏差——真信号是腾讯 DMCA 趋严（外生冲击），repo 热度只是噪声；紧迫性来自 DMCA 不来自星数。决策已八分预定（路线 c），真正待实证的只有解密能否跑通。fork>star 也可能是「跑不通才去修」的负信号。
Proposal #2 · AI Coding Eval 🔬 可视化栈Skill Hub v5

双层 Agent 可视化表达栈：show-me（即时理解）× drawio-skill（正式交付）

核心主张：用 show-me 补齐「会话内即时可视化」缺口，把 agent 输出从「读不完的长文本」变成「秒懂的最小视图」，并将「可视化是否提升人工评审效率」做成可测量、可复现的工程结论。价值不在安装（复制即用），在制度化使用。

🚩 里程碑

  • M1（本周）：入个人 skill 目录，三场景实测（eval 解读/架构讨论/review），记基线
  • M2（09-14~20）：与 drawio 分工决策卡成文（分界不在格式，在归宿：即抛 vs 长期维护）+ A/B 方案定稿
  • M3（09-21~10-09）：≥2 评审者 × ≥20 任务 A/B（带视图 vs 纯文本）出数
  • M4（10-16 前）：Skill Hub external 收录提案（首个「纯 prompt 类」示范）

📏 成功标准

  • 评审耗时中位数降 ≥25%；漏判率不升（防「图漂亮但漏问题」）；agent 端耗时增幅 ≤10%；不显著则如实报告、止步个人层
诚实挑战：收藏家陷阱——个人 skill 已 200+，无场景锚定终成摆设，只押 eval 评审一个场景先证明；名人效应溢价——本质是一段好 prompt，30 分钟可自写八成版本，稀缺处仅是视图选型分类学；要制度化的不是这份文件，而是「agent 默认附最小视图」的习惯。
Proposal #3 · Life OS 数据层 📚 上周遗留补深挖

lse-lite：窃 Linear 同步引擎 20% 内核，300-500 行微型同步层

核心主张：不自研 Linear 级引擎，只取其内核——单调 sync id + append-only op log + last-writer-wins fold——在 git 之上写微型同步层：不同步 SQLite，同步 op log；每端从 log 物化自己的 SQLite。git 从「合并难点」降级为「纯传输层」。其余 80%（WebSocket 实时/partial index/undo）明确不做。

📋 信号核验修正（本次三源亲查）

  • 引语修正：Linear 工程师 "pretty awesome" 原句未见；可查证原文为 Linear CTO Tuomas Artman："correct and more complete than what Linear publishes internally"
  • HN 评论降维金句："log updates in a DB table and, on reconnect, fetch everything after the last-seen ID"——引擎种子就这么大

🚩 里程碑（四周决策门 9/28）

  • W1：通读 repo + SUMMARY，八项决策两栏表（Linear 怎么做 / 我怎么做）
  • W2：lse-lite v0——JSONL op log + SQLite 物化 + LWW fold，50+ tests
  • W3：接入 journal 真实数据流，双机经 git 跑一周
  • W4（9/28 决策门）：分钟级够 → 归档；要秒级 → CF Worker + D1 免费层

📏 成功标准

  • 2 设备×3 agent 交错写 1000 ops 物化后字节级一致 0 丢写；30 天手工解冲突 = 0；核心 ≤500 行；删库可从 op log 完整重建
诚实挑战：你可能不需要同步层，需要的是减少写入点——把写收敛到单写者，P1/P3 当场消失；先回答「为什么我的 agent 必须多机并发写」，答不出就是为不存在的问题打地基。最简反方案：append-only JSONL + compaction + jq，连 fold 都不用写。本项目一半是基建一半是学习，四周后若只有模式摘要也算成功，但须如实标注。
Proposal #4 · K12 Education 🎓 方法论继承

K12 教材数字化管线：继承方法论，更换语料

核心主张：AI 教室的天花板不在模型，在素材——公式若只是图片，LLM 便读不懂数学，出题即幻觉。继承「OCR → LLM 校订 → LaTeX 结构化 → 可检索知识库」管线（成本已证可控），语料走公版书 + 自产内容；版权教材永不入线上库。与课程大纲是平行线非依赖——接口先定，两边并行。

🚩 里程碑（业余 6h/周）

  • M0（9/14）：MinerU vs Mathpix 选型 spike，20 页样张公式抽检
  • M1（9/30）：单章端到端 → 本地可检索
  • M2（10/31）：1 本公版数学书 + 200 自产题，schema 定稿
  • M3（11/30）：AI 教室只读知识库 + 出题工作流，试讲一次
  • M4（12/15）：扩大 / 暂停 / 谈授权三选一

📏 成功标准

  • 100 公式抽检 LaTeX 可编译率 ≥95%；单章人工介入 ≤2h；试讲中 agent 出题 80% 附出处；线上库受版权内容 = 0
诚实挑战：版权风险不否定管线，只否定语料——《数理化自学丛书》非确认公版（集体署名、出版社权益仍在，网络扫描版≠合法）；真瓶颈可能是内容判断力而非管线（若难题在「什么题值得出」，应降级管线为 skill）；「LLM 读懂公式」或被高估——结构化提升的是检索与引用，非推理能力。
Proposal #5 · AI Starter Kit 🩺 doctor 模式复用

sk-doctor：把 Mac bootstrap 从「安装流水线」重构为「自检先行的修复协议」

核心主张：环境问题的第一响应从「问人」变为「跑 sk-doctor」——分项自检、[ok]/[!!] 结构化输出、每项失败附 agent 可执行修复指令（三级 safe_level），支持 --fix 一键修复。signal-vaults 的真正增量不在「有 doctor」（brew/flutter 先例），而在输出同时格式化为 agent 修复协议——人机两读。

🚩 里程碑（8 周）

  • M0：失败点盘点（changelog + 近 3 月求助记录 + 真机实测）→ 检查项清单 v0
  • M1-M2：Bun+TS MVP，12-15 项检查，终端 + --json 双格式，README 内嵌 agent 提示词
  • M3：团队试点，--json 定为远程支持标准接口
  • M4：抽 env-doctor 通用框架，反哺个人 200+ skills 管道前置自检

📏 成功标准

  • onboard 环境 ready 0.5-2 天 → <2 小时；环境求助消息 -70%；已知失败点覆盖率 ≥90%；--fix 一次成功率 ≥60% 且修后复检 exit 0 闭环
诚实挑战：先例证明真正难的从来不是输出格式，而是检查项判定逻辑的持续维护；规模诚实——11 人团队若月求助 <5 次，一个 README 章节可能就够，先用 M0 数据决策，不拍脑袋立项；macOS 硬边界（Gatekeeper/sudo/全盘访问）决定「一键修复」上限约 60-70%。
