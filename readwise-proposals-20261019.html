P2 · Linus 案例作为练级场旗舰证据

一案三证：性能上限 · 人类终审 · 揪出即接棒

信号：Linus 用 Claude Code 改内核（✅ InfoQ 全文）· 连接：D1 练级场 / P1 审查重构 / 讲师团
以 Linus 案为练级场叙事旗舰证据：读取吞吐最高 23×，竞争条件 bug 靠维护者 Shutsemau 合入前揪出，后续开发移交揪 bug 者——正合「策略者/裁决者/审计者」三层与人上移叙事，并顺势立「AI 参与透明标注」试行规范。

① 叙事萃取：三金句 × 场景

金句内部场景
23× 性能与竞争条件 bug 并存——「能跑」与「正确」分离讲师团 L0 开场：AI 输出默认高性能草稿，正确性另判
提交记录透明标注 AI 参与——免责与诚信的规范雏形提案论证：向管理层证三层模型时引为业界风向
后续交给揪 bug 者——审查即练级、揪出即接棒团队规范起草：「谁揪出谁接棒」入审计者晋升路径

② 制度落地：「AI 参与透明标注」试行草案

提交信息尾注 AI: none|assist|pair|gen + 一句人类验证范围（已审什么/未审什么）。防退化设计：标注驱动审查分流（`gen` 必入终审队列）；审计者月度抽查失真率；失真 >20% 复盘入 case bank 不罚个人——护住诚实标注。

③ 论证边界（与 P1 杀门的关系）

本案只证明「终审需要人」，不证明「人人需要审」——恰支持 P1 的杀门方向：价值在专职终审，不在全员全量审。本案仅作叙事证据不作数据证据；引用时明示边界，防「业务代码非内核」一击即溃。里程碑：W1 金句卡入库 + 草案半页评审 → W2-3 一两个 squad 灰度 → W4 全组试行 + 首次失真率抽查。成功标准：灰度标注覆盖率 ≥90%、抽查失真率 ≤20%、`gen` 提交 100% 过终审、讲师团 3 场后学员能复述「能跑≠正确」。

⚡ 本周三件事
