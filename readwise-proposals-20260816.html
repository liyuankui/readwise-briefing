#1 · AR-SI：Adversarial Review as Standard Infrastructure

AI Coding EvalTesting Excellenceopencode-proposal信号：@bcherny ✅
核心主张：在 FTP 短期不可得的约束下，「独立上下文、穷举失败理由」的对抗性评审应同时部署为 eval 的第二裁判、团队 PR 的质量闸、opencode 的差异化叙事——同一机制，一次构建，三处复用，且每处都有内外数据双重支撑。

三个经得起追问的支点

支点证据追问的答案
机制有外部背书Jarred Sumner（Bun@Anthropic）53.5 万行重写的核心实践；Cherny（Claude Code 负责人）称 "incredibly powerful tool"不是我们的发明，是头部团队的既定工程实践
痛点有内部数据judge_only 三模型挤 57–59%；重跑对照实验暴露 judge 30pp 高估见下，非泛泛而谈
一次构建三处用eval 的对抗 judge 与 PR 的对抗 reviewer 是同一个 prompt 同一个模型角色评测即工作流 dogfood，成本摊薄 3 倍

锁定的痛点

  • P1 零区分度：n=56 矩阵三模型极差仅 1.6pp（59.1 / 57.5 / 57.5%），n=56 置信区间约 ±13pp——差距完全淹没在噪声里，选型决策卡死。
  • P2 裁判系统性放水（已抓包）：08-04 重跑对照——judge 给 10/10，真实自主重跑仅 7/10，30pp 高估由人工重跑才发现；确认"纯 diff 盲评无法识别编译/测试失败"的方法论盲区。
  • P3 火力停旧靶位：Cherny 论断 bug 从 off-by-one → system design / usability / context；内部矩阵完全互证（最难=跨文件领域改造，最易=局部 DTO）。
  • P4 opencode 只有成本故事没有质量故事："便宜模型"触发 cheap=cheap 异议；adversarial reviewer 是"便宜模型干高价值活"的最佳叙事。
机制定义（fork Jarred 原句）：独立 context window（非 solver 会话），要求模型"穷举这个改动会制造 bug 或不成立的理由"，每条必须引用 file:line 证据 + 可执行验证建议，输出结构化 verdict。裁判模型 ≠ solver 模型。

ROI

  • 选型解锁：11 工程师 × 仅 5% 效率差 ≈ 0.55 FTE ≈ 28.6 人周/年；现状是数周 eval 投入换不来任何决策。
  • 评审产能：分级 token 费 vs senior 30min/PR 人工审查——量级差 10³–10⁴，等效一个不知疲倦的二审。
  • 逃逸损失：跨文件领域 bug 出现在订单域 = 事故级，一次逃逸代价 > 全年 reviewer token 费。

风险与缓解（节选）

  • 对抗 judge 统一压分（severity bias）→ 种子校准 + FPR 硬门 + 双裁判分歧人工仲裁
  • 便宜模型审不出 system-design bug → 喂 repo context + 任务书而非裸 diff；捕获率不足则降级"初筛+强模型复审"
  • 告警疲劳 → 影子模式起步、top-3 封顶、ignore 率 >50% 触发 kill switch
  • judge 与 solver 同家族自我偏好 → 裁判强制 ≠ solver，交叉裁判矩阵

立即行动（本周 3 件）

  1. 对抗 judge prompt v1 + 重判存量：双裁判配置跑 56 个历史产物 + 重跑 case，出 spread delta 表。纯 token 成本，本周出结果。
  2. 10-patch 种子校准集：5 好 + 5 坏出 TPR/FPR；顺手给 56 个 diff 打 bug taxonomy 标签（局部 vs 跨文件），用自有数据验证 Cherny 迁移论。
  3. opencode 一页纸："Adversarial Reviewer——便宜模型干高价值活"，证据链 Cherny → Jarred → 内部矩阵，附进合规咨询；同步收 2 个试点 repo 志愿者。

🚩 诚实挑战（节选全文 6 条之要）

  1. 噪声放大是最大威胁：可能惩罚"敢做跨文件改造"的模型、奖励"最怂的"——M0 必须看分布与分层极差，种子校准不过门就砍。
  2. "模型等价"是完全合法的另一种结论：±13pp 置信区间分不清"裁判看不出"和"真没差距"——M0 可能给出"停止优化选型、全押工作流"的答案。
  3. Cherny 观察有选择偏差：Claude 系 + TS/系统编程；我们是 Java 订单域 + 便宜模型，内部数据只证明"跨文件难"，没证明"低级 bug 已消失"。
  4. 无构建环境下是"对抗性阅读"，强度低一档——需与离线构建路线配对抽查执行。
