P1 · AI 代理重写架构选型经济学：对门店 POS 的三点落地

选型第一问从「如何共享代码」变为「如何让 agent 可验证地写对代码」

信号：Why Shopify Migrated From React Native（✅ ByteByteGo 转述，量化以 Shopify 原博为准）· 连接：Store POS 现代化（前端/BFF 待定）/ Agent-Native 维度 / D1-P1 审查体系
AI 编码代理使「重复实现」边际成本大降——跨平台共享不再默认省钱；可验证性升为硬约束。

锁定痛点

POS Phase 2 已立项，前端/BFF 架构待定；讨论仍以「复用率」为共享层主论据，缺 AI 时代成本重算框架。

① 选型原则修订：共享收益公式重算

双端各自实现成本系数从约 2.0 降至 1.2~1.5，共享层节省从 1.0 缩到 0.2~0.5，而抽象税（接口妥协、版本协调）不变——净收益可能转负。

成本项AI 时代变化
双端重复实现大降
共享层抽象税不降
QA 面不降：双端双倍验证，强合规下 QA 是主成本
设计一致性不降：双套 UI 对齐成本仍在
团队认知负荷升：11 人撑双技术栈更紧

B2B 单端场景「复用」论据降权；BFF 共享业务逻辑仍成立，但须以重算后净收益立项。

② 「无头 CLI 供 agent 验证」升为架构硬约束

Shopify 敢把重写交给 agent，前提是 agent 能用 CLI 快速验证状态。POS 交易核心同理：每个服务提供只读、幂等、结构化的 verify 入口（订单状态/对账快照/幂等结果），与「Agent-Native 可调用性」合并为一条团队原则：服务须同时暴露 human API 与 agent 可验证接口，否则不得上生产。

③ 小步迁移检查点对接 D1/P1

对标 Shopify 的 Helix 多重复核：AI 代码质量门 = L1 gate；小步检查点 = 每 PR 一个可验证行为切片；D1 增「agent 可验证性」栏，P1 要求附 agent 自验输出。

里程碑与成功标准

W1 BFF 讨论会用清单重审方案 → W2 挑 1 个 POS 服务试点 verify CLI → W4 D1/P1 模板增补 + 沉淀 ADR。可测：BFF 评审记录含逐项成本重算；试点服务 agent 验证调用 P95 <2s 且覆盖 ≥3 个核心状态；AI 代码返工率较基线降 ≥30%。ROI：省共享层抽象税约 0.5~1 人力/年；verify 入口复用于巡检与 oncall。风险：认知负荷被低估（原则只约束新选型）；verify 暴露敏感态（只读 + 最小字段 + 审计日志）。
