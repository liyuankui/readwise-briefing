Proposal 04 · Testing Excellence
IAT — 意图锚定测试法：替代 AI 时代失效的 TDD
AI 不理解测试背后的意图，只优化"让测试变绿"——解法是用「意图规约（Gherkin Spec）」+ Mutation Testing 让 AI 的优化目标与用户真实问题对齐。
~3 人·月

🎯 四层防线机制

层机制工具
Layer 1行为规约先行：工程师（非 AI）用 Gherkin 写业务意图Cucumber (Java) / godog (Go)
Layer 2AI 从 Spec 派生代码 + 测试（Prompt 强制引用 Scenario 编号）Copilot / Claude
Layer 3Mutation Testing CI 门禁（初始 60%，升至 75%）PIT (Java) / gremlins (Go)
Layer 4AI 代码 PR 专项 Checklist（意图追溯 + 边界验证）GitHub PR Template

Gherkin 规约模板落地（Order/Inventory/Search 各一示例）；半天 Workshop 训练团队"人写意图 → AI 写实现"

🔴 诚实挑战

⚠ Gherkin 有学习曲线：如果团队不接受，可降级为"结构化注释 + ADR"，保留意图规约精神，去掉工具门槛。Gherkin 是理想，不是必要条件。

Proposal 05 · Life OS · Skill 标准
HTML-First Agent Output Standard：从个人习惯到组织标准
Agent 的输出不是文档，是界面——IKEA 的 Skill 标准应从"生产 Markdown"转向"生产 HTML"，以"消费质量"而非"编辑便利"作为第一评价标准。
~2 人·月

🎯 核心决策规则

输出用途格式
人类最终消费（报告、摘要、briefing、邮件草稿）HTML
Agent 继续处理的中间产物（Spec、prompt、代码注释）Markdown
版本控制核心文档（VISION、AGENTS、CLAUDE）Markdown（永远）
交互 / 可视化需求（dashboard、对比表、日志）HTML

🗺️ 实施里程碑

M2 · 第 3-4 周 · 16h
改造 5 个最常用 Skill 输出 HTML（readwise-briefing / cdhf-oncall-doctor / dayflow-insight / article-improver / delivery-closure）；Skill SPEC 新增 Output Contract 声明
